# 실행부의 지도 준비와 음향 태그 계약

변경 대상은 새 실행부와 그 별도 배포 묶음이랍니다. SDK 인터페이스·GameCore 객체 배치·게임 저장 필드·모드 ID·버전·밸런스는 변경하지 않사와요. 실제 GameCore 로딩 허가는 아직 답변을 기다리는 중이므로 독립 서비스와 실제 자료 조회로 검증하와요.

## 요구사항과 수용 기준

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| MA01 | `DoMapSetup`이 실행부의 지도 상태를 준비 | 타일 수에 맞는 새 표시 갱신 상태와 세대 번호를 한 번에 게시; 0 크기 허용, 음수 거부 |
| MA02 | 실패와 오래된 참조 방어 | 할당 실패 전후 현재 지도 동일; 이전 불변 스냅숏 유효; 종료 시 현재 지도 분리; 새 세대에서 이전 타일 상태 재사용 금지 |
| MA03 | 지도 변경 소유권 | 활성 실행부·게임 소유 스레드·GameCore 잠금 상태에서만 SDK 지도 준비 호출 허용 |
| MA04 | 실제 음향 태그 목록 | 설치 XML의 실제 정의를 읽어 이름·설명·종류가 연결된 세션용 ID 제공; 상수 성공값 금지 |
| MA05 | 미지원·누락 구분 | 미지원 음향 종류는 이름 있는 예외; 없는 태그는 -1과 별도 누락 기록; 별칭이나 자료를 임의 생성하지 않음 |
| MA06 | 자료 출처와 배포 | 원본 XML·규칙 DB·생성기·카탈로그 해시, 원본 무변경, 묶음 검증과 재현 가능한 생성 |

위 요구사항은 독립 실행부 서비스 범위에서 검증했사와요. 소유 스레드의 새 전역 초기화는 이전 UI 상태·선택 횟수·종료 표시·누락 음향 기록을 정리하와요. 실제 GameCore와의 통합 실행·표시 소비자·음향 재생은 완료 기준이 별개랍니다.

지도 상태는 이후 표시 소비자가 읽을 타일별 갱신 표시와 세대를 소유하와요. 지형 렌더링이나 게임 규칙 상태를 대신하지 않으며, 할당 실패 뒤에는 기존 상태를 그대로 유지하와요.

음향 ID는 이 실행부가 소유하는 카탈로그 안의 번호이와요. 실제 SDK에서 이 값은 정보 객체에 적재되어 실행부 조회 인터페이스로 반환되며, 이번 범위의 저장 필드로 추가하지 않사와요. 기존 비공개 실행부의 숫자 ID와 동일하다고 주장하지 않으며 실제 음향 재생과 기존 저장 전체의 동등성은 별도 관문이랍니다.

설치된 환경음 XML에는 `ASSS_AMBIENCE_TUNDRA` 정의가 없지만 보유 규칙 DB는 이를 참조하와요. 이를 `SNOW`로 바꾸거나 임의 ID를 만들지 않고 누락으로 기록하와요. 이 -1 처리의 기존 실행부 동등성은 아직 미검증이랍니다.

## 실행 검증 결과

`Tests/sdk_host_map_audio.cpp`는 실제 실행부 어댑터를 통해 12,615개 단언을 통과했사와요. 지도 두 할당 위치와 음향 카탈로그의 48개 할당 위치에 실패를 넣어 기존 지도 보존·임시 메모리 반납을 확인했답니다. 잘못된 길이·중복 이름·절단·끝의 여분·잘못된 태그·NUL 등 81개 잘못된 카탈로그를 거부했사와요.

지도 교체 128회와 작업자 8개의 불변 지도 읽기 4,096회·음향 조회 8,192회를 실행했사와요. 이전 스냅숏의 크기·세대·갱신 표시는 새 지도와 종료 뒤에도 유지되었고, 다른 소유 스레드의 지도 준비·전역 초기화·종료를 거부했답니다. 이는 게임 계산 병렬화나 턴 시간 개선의 증거가 아니랍니다.

실제 XML 3개에서 환경음 10개, 참조 2D 스크립트 33개와 음원 정의 33개를 확보했사와요. 카탈로그는 이름뿐 아니라 해당 정의와 참조 XML을 함께 보유하며, 네이티브 조회 결과의 전체 설명 바이트와 별도 Python 계산이 일치했답니다. 실제 한·영 데이터 점검에서도 규칙 태그 8종 중 7종은 해당 정의에 연결되었고 툰드라 1종은 -1·누락 이름으로 확인했사와요. 모든 음원을 재생하거나 실제 파일을 디코딩한 시험은 아니랍니다.

지도·음향 단계 당시에는 수명 시험 3,937개와 합계 16,552개 단언, 프로세스 19개를 통과했사와요. 후속 실제 Lua 서비스 연결은 [스크립트 검증](M3_HOST_SCRIPT.md)에 기록하와요. 실제 데이터 단계에서 카탈로그 파싱 실패 후 DB·현지화 정리도 확인했답니다. 기록은 `evidence/host/conformance.json`, 원본과 카탈로그 대응은 `evidence/host/audio_catalog.json`에 있사와요.

## 별도 실행 묶음의 변경

실행부 묶음에 `audio-catalog.bin`을 추가하면서 검증 목록은 `ZEROSIS_HOST_BUNDLE_V2`·8개 파일로 전환하와요. 이는 신규 실행부 후보의 내부 배포 형식이며 게임 저장 스키마와는 별개랍니다. 생성기는 이전에 기록된 v1 Stage 파일의 해시를 확인한 뒤 v2를 만들고, 새 실행부는 v1을 명시적으로 거부하와요. 원본·기존 MODS·저장 파일은 이 전환 대상이 아니랍니다.
