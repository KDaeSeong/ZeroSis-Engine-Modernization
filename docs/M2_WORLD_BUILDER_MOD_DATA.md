# 지도·타일 부가 데이터 x64 연결

2026-09-25. 실제 SDK 부가 데이터의 원본 비교와 독립 구성요소 실행 검증이랍니다. 전체 지도 파일이나 게임 실행 검증은 별도랍니다.

## 요구사항과 변경 범위

지도와 타일에 붙는 bool·float·string·enum 값, 필드 이름·기본값·열거형 이름 목록, 32비트 저장 폭을 보존하와요. 참조는 설치 SDK의 실제 x86 `CvWorldBuilderMapWin32.lib`이며 새 제공자는 원본 클래스 서명·객체 배치를 유지한 x64 코드랍니다. 설치 SDK·게임 EXE/DLL·지도·MODS·저장 파일은 변경하지 않사와요. ID·스키마 번호·밸런스 변경도 없답니다.

`SdkWorldBuilderModData.cpp`가 실제 SDK 클래스 본체를 제공하고 `SdkWorldBuilderModDataWire.cpp`가 길이를 받는 저장 자료 읽기와 쓰기를 담당하와요. 접근 선언 6개만 SDK 부가 데이터 클래스와 배열에 추가했으며, 필드·가상 함수·공개 SDK 서명·저장 형식은 유지하와요. 기존 482개 패치를 그대로 보존한 **488개 패치·63개 수정 SDK 파일**로 GameCore **161개**를 다시 컴파일했사와요.

## 소유권과 교체 계약

필드·열거형·멤버 목록·문자열·자료 배열은 먼저 별도 소유 버퍼에서 완성한 뒤 할당 없는 절차로 교체하와요. 준비 실패 시 이전 값과 할당을 보존하와요. 내부 SDK 배열의 성장 함수를 사용하여 용량만 먼저 바뀌는 경로는 이 제공자에서 사용하지 않사와요. 정상 실행에서는 검증된 Foundation의 정렬 할당·반납을 사용하와요.

문자열은 원본처럼 중복 문자열도 별도 위치에 추가하와요. 기본값 여부는 저장된 32비트 값으로 비교하므로, 기본값과 같은 문자열을 새로 설정해도 다른 문자열 위치를 가지면 기본값으로 표시하지 않는 원본 동작을 유지하와요. 다중 열거형은 저장 타입 값 `3 + 열거형 인덱스`를 유지하고 공개 타입 조회에서는 `TYPE_ENUM`을 반환하와요.

`ZeroSisWorldBuilder::DeserializeModData(target, bytes, length)`가 파일 독자용 경계랍니다. 잘린 자료·잘못된 개수와 참조·누락 종료 문자·뒤에 붙은 자료를 거부하며 대상은 그대로 유지하와요. 원본 SDK의 `Deserialize(const void*)`에는 길이가 없으므로 **이미 길이를 검증한 신뢰할 수 있는 버퍼만** 전달해야 하와요. 향후 지도 파일 독자는 반드시 길이 있는 경계를 사용하고 지도 헤더의 타일 수와 자료 배열 크기도 대조해야 하와요.

`ModDataEntry`와 열거형·문자열 포인터는 소유 객체에서 빌려 쓰는 값이랍니다. 필드 구조 변경 뒤 `InitDataEntries`를 다시 호출하고, 자료 재할당·역직렬화·초기화 뒤에는 기존 엔트리/포인터를 다시 얻어야 하와요. 동일 객체를 여러 스레드에서 수정하는 기능은 지원 계약이 아니랍니다.

## 원본 비교와 보완

원본과 후보를 **17회 실행·6,752회 검사**로 대조했사와요. 정상 비교 4개 모드는 기본 자료, 17개 전역 필드와 12개 열거형, 기본값·중복 문자열·음수 열거형, 잘못된 메타데이터 인덱스를 포함하와요. 2,551바이트 자료가 두 아키텍처와 독립 Python 형식 모델에서 일치했고, 양방향 네 차례 읽기도 일치했답니다.

원본에서는 타일 값을 99로 설정한 뒤 타일 수를 0으로 줄였다가 1로 늘리면, 새 항목에 이전 메모리의 99가 다시 나타났사와요. 후보는 새 항목에 선언한 기본값 17을 설정하와요. 이 초기화 보완의 한 줄 차이만 비교 도구가 명시적으로 허용하며 다른 차이는 실패로 처리하와요. 유지되는 기존 항목의 값은 보존하와요.

후보 경계 검사는 **6,104회**이며 잘린 입력 **1,904가지**, 잘못된 문자열·열거형 참조, NULL·범위 초과·크기 넘침·별칭 문자열·초기화와 해제를 확인하와요. 9종 작업에서 **할당 실패 442건**과 성공 경로를 확인했으며 실패 때 직렬화 결과와 살아 있는 할당 수가 유지되었사와요. 실패 할당기는 시험 실행 파일에만 연결하며 제품 오브젝트를 그대로 사용하와요. 정상 소비 프로그램은 실제 Foundation 할당기를 사용하는 것을 연결 지도로 대조하와요.

작업자 4개의 독립 객체 생성·저장·읽기 **256회**를 확인했사와요. 직접 작성한 제품과 시험은 `/MD /W4 /WX`에서 경고 없이 빌드되었답니다. 이는 공유 GameCore 계산의 병렬화나 턴 시간 개선을 입증한 결과가 아니랍니다.

## 연결과 남은 관문

실제 제공자로 **16개** 연결 항목을 해소하여 **33→17개**로 줄였사와요. 남은 것은 지도 본체·파일 처리 13개와 파일·로그·디버그 서비스 4개랍니다. GameCore DLL은 아직 생성되지 않았고 로드·게임 실행도 하지 않았사와요.

전체 지도 파일의 버전별 읽기·쓰기·시나리오·실제 자산 왕복, 지도 헤더와 타일 수의 일치, 전체 GameCore 실행은 남아 있사와요. `CvWorldBuilderMapLoader::LoadModData`의 전역 열거형 경로가 타일 열거형을 조회하는 호출부 결함 후보도 별도 재현·수정 대상으로 남겨 두었답니다. 이번 구현을 그 호출부 검증 완료로 계산하지 않사와요.
