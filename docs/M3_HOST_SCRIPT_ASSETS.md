# 실행부의 게임 라이브러리·지도 Lua 자산 연결

2026-09-27 작업 계약이와요. 대상은 새 실행부의 스크립트 서비스·수명 연결·자료 묶음이며, 게임 규칙·기존 저장·모드 식별자는 변경하지 않사와요. 설치 자료는 읽기 전용으로 조사하고 원본과 일치하는 별도 Source 사본에서 Build와 Stage를 생성하와요. 실제 GameCore 로딩 허가는 아직 대기 중이므로 이번 독립 검증이 게임 구동을 증명하지는 않사와요.

| ID | 요구사항과 완료 기준 |
|---|---|
| SA01 | 설치된 기본 지도와 Gameplay Lua, Expansion·Expansion2 Gameplay Lua를 원본 바이트와 해시로 보존하고 선택 출처·덮어쓴 파일을 기록 |
| SA02 | 새 호스트의 명시적 BNW 선택 순서로 자료 묶음 생성, 경로·별칭·길이·중복·손상 검사, 게임 설치 경로를 직접 탐색하지 않는 실행부 |
| SA03 | 실제 LoadFile·include 연결, 중첩 호출·순환·누락·실행 오류·할당 실패 뒤 복구, 호출별 원본 내용 보존 |
| SA04 | SDK GetScriptSystemUtility로 받은 빌린 인터페이스를 새 VM의 RegisterScriptLibraries에 연결, 등록 실패 VM 미게시·종료 전 라이브러리 수명 보존 |
| SA05 | 실제 보유 지도 스크립트 적재와 메타데이터 실행; 게임 객체를 꾸며 넣지 않고 부족한 API는 실패로 표시 |
| SA06 | 실제 게임 라이브러리 연결 코드와 계측 대체 인터페이스 시험을 구분; Source→Build→Stage와 독립 실행 근거 갱신 |

파일 선택은 기본 Gameplay Lua 위에 Expansion, Expansion2의 같은 논리 경로를 순서대로 적용하와요. 기본 지도 폴더는 별도 논리 경로를 사용하와요. 이는 새 실행부의 명시적 구성 계약이며 원래 EXE의 모든 DLC·사용자 모드 검색 순서를 재현했다고 주장하지 않사와요. 사용자 모드·시나리오·추가 지도팩 선택은 해당 활성화 목록과 충돌 규칙을 확보한 뒤 확장해야 하와요.

LoadFile은 논리 경로·선택된 원본의 Assets 상대 경로·유일한 파일 이름을 허용하와요. 파일 이름만으로 둘 이상이 일치하면 실패하와요. ASCII 대소문자와 역슬래시를 정규화하고 생략한 `.lua` 확장자를 보완하며, 절대 경로·상위 폴더 이동·NUL·잘못된 구성요소는 거부하와요. 바이트는 그대로 보유하고 적재할 때 UTF-8 BOM만 건너뛰도록 하와요.

include는 현재 VM에서 매 호출마다 실행하고 같은 VM의 실행 중 파일을 다시 포함하는 순환은 거부하와요. 일반 파일 적재는 자동 캐시하지 않으며 include의 반환값은 없사와요. 원본의 캐시·반환 규약은 비교 전이랍니다. 패턴을 사용한 include의 추가 옵션은 명시적 미지원이며, 설치 GameCalendarUtilities가 사용하는 선택적 패턴 적재는 후속 범위로 남기와요.

게임 라이브러리는 GC.Init 뒤에 연결하고 새 VM 생성 시에만 등록하와요. 기존 VM을 둔 상태의 바인딩 교체·등록 중 재진입은 거부하와요. 등록·반납에는 소유 스레드와 GameCore 잠금을 요구하며 라이브러리 소유권을 가져오거나 임의로 Destroy하지 않사와요. GC.Uninit 후 남은 VM을 닫고 엔진 연결·모듈을 해제하는 순서를 유지하며, 실제 게임 객체 finalizer와 SDK C++의 Lua longjmp 경계는 실제 등록 실행 전에 추가 검토해야 하와요.

신규 실행부 묶음은 `script-catalog.bin`을 추가한 `ZEROSIS_HOST_BUNDLE_V3`·9개 파일로 전환하와요. 이전 v2의 기록된 해시를 확인한 뒤 별도 Stage를 갱신하고 v1/v2 실행 묶음은 명시적으로 거부하와요. 게임 저장 스키마의 변경은 아니랍니다.

## 구현과 실제 실행 결과

`prepare_host_script_catalog.py`가 설치 Lua 원본 46개를 별도 Source에 같은 바이트로 보존하고, 같은 논리 경로의 교체 10회를 기록하여 선택 파일 36개·1,094,197바이트의 카탈로그를 만들었사와요. `ScriptCatalog`는 선택 출처와 본문을 보유하며 모호한 별칭을 거부하고, 객체를 복사할 수 없게 하여 내부 파일 포인터의 수명을 고정하와요.

`ScriptSystem`의 LoadFile과 include가 이 자료를 읽으며, 실제 GameCore 초기화 코드에는 `GetScriptSystemUtility` 바인딩을 연결했사와요. 실패한 VM의 finalizer가 실행되는 동안에도 등록 중 상태를 유지하여 재진입·전체 종료를 거부하와요. 실제 DLL은 로드하지 않았으며 게임 라이브러리 등록의 호출·실패·소유권 검사는 계측 인터페이스로 수행했답니다.

| 검증 | 관측 결과 |
|---|---|
| 보유 Lua 자료 | 선택 파일 36개의 네이티브 조회 바이트와 Python의 원본 지문 일치 |
| 실제 기본 지도 스크립트 | 18개 모두 적재·GetMapScriptInfo 실행; 이름·설명 키가 각 원본의 반환문과 일치 |
| 카탈로그 손상 | 절단·버전·길이·중복 경로·출처 충돌·잘못된 경로 등 79개 거부 |
| 카탈로그 C++ 할당 실패 | 498개 지점; 부분 생성 자료 반납 |
| 중첩 include 실패 | C++ 할당 실패 6개·Lua 할당 실패 69개; 스택·실행 중 파일 표시 복구 뒤 재실행 성공 |
| include 의미 | 재호출 실행, 순환·누락·문법/실행 오류·NUL/상위 이동·미지원 패턴 거부, UTF-8 BOM 적재 |
| 게임 라이브러리 등록 | 잠금·바인딩 교체·재진입 거부, C++/Lua 등록 오류 뒤 미완성 VM 미게시, 빌린 인터페이스 Destroy 0회 |
| GameCore 연결 실패 | 계측 문맥에서 인터페이스 조회 전·후 실패와 nullptr 3개 경계, GC/어댑터/스크립트 정리 |

자료·등록 전용 시험은 **1,076개 단언**을 통과했사와요. 현재 전체 실행부는 수명 4,056개·지도/음향 12,615개·Lua 3,201개·자료/등록 1,076개, **합계 20,948개 단언·24개 프로세스 실행**이랍니다. 다섯 실행 파일은 경고 없이 빌드되었으며 v1/v2·누락 스크립트 자료·손상 카탈로그 등을 포함한 잘못된 실행 묶음 14개를 거부했사와요. 한·영 실제 데이터 점검에서도 Continents의 원본 스크립트와 중첩 의존성을 적재해 이름·설명·옵션 5개를 확인했답니다.

이 실행부 검증은 지도 정보 함수를 실행한 결과이며 지형·도시·유닛을 생성하거나 게임 턴을 진행한 결과가 아니랍니다. 아래의 등록·프랙탈 독립 시험과도 구분하와요. 실제 GameCore가 등록하는 7개 라이브러리 전체, 게임 객체의 수명·원본 호환성과 게임 멀티코어는 미검증 상태이와요.

## 다음 결함과 미지원 범위

차용 참조 후속 통합에서는 공통 템플릿의 VM·자료형·표 식별, 수명 경계 34곳, 네이티브 래퍼 4종과 거래 자기 복사 보존을 정식 SDK에 반영했사와요. 실제 Lua와 정확한 함수 본문·SDK 컨테이너를 사용한 독립 검사 27,168개를 통과했으며, 등록 시험은 새 템플릿 전체를 사용하여 243,512개로 갱신했답니다. 감사 기록의 `borrowed_component`가 이 근거를 연결하와요. 게임 소유자·서비스는 계측 대체물이므로 `SCRIPT-OBJECT-LIFETIMES`는 실제 소유자·실행부 오류 처리·종료 순서 검증을 기다리는 열린 항목으로 유지하와요. [정확한 수명 검증 범위](M3_LUA_BORROWED_OBJECTS.md)

`script_binding_audit.json`은 실제 SDK 함수 6개와 등록 순서 `CvLuaEnums → CvLuaFractal → CvLuaGameInfo → CvLuaMap → CvLuaGame → CvLuaPlayer → CvLuaTeam`을 기록하와요. `CvLuaEnums`의 DB 준비·반복·개수 조회 실패와 보호 호출의 실패 반환 무시는 실제 함수·DB·Lua·FLua 시험으로 재현하고 수정했사와요. 원본 longjmp 누수 의심은 MSVC x64 `/EHsc /O2`·`/EHsc /Od`에서 재현되지 않아 기록을 정정했답니다. 정확한 범위와 5,808개 검사 결과는 [열거형 오류 경계](M3_LUA_ENUMS.md)에 있사와요.

후속 [등록 실패 전달 단계](M3_LUA_REGISTRATION.md)에서 나머지 여섯 등록 경로와 전체 순서의 정확한 함수 본문 22개를 별도로 실행했사와요. 메서드 1,228개의 등록과 일곱 실패 경계, Lua 할당 실패를 포함한 223,184개 검사를 통과했으며 감사 기록의 `registration_component`로 연결하와요. 이 등록 시험의 게임 메서드와 객체 소유자는 계측용 대체물이랍니다.

[프랙탈 후속 단계](M3_LUA_FRACTAL.md)는 VM이 소유하는 userdata의 형식·중복 소멸·실패 정리와 선택 인수의 기본값을 보완했사와요. 정식 생성 SDK와 같은 본문으로 48,986개 검사·22개 프로세스를 통과했으며 감사 기록의 `fractal_component`로 연결하와요. 계측 수명과 별도 실제 계산의 난수·컨테이너 어댑터 범위를 기록하며, 실제 동적 자원 누수가 입증된 것으로 표시하지 않사와요. 감사 기록은 해당 문제를 해결 항목으로 옮기고, 차용한 플레이어·도시·유닛의 수명과 실제 GameCore 종료 순서는 계속 미해결로 남기와요.

프랙탈 수치 경계는 [수치 후속 단계](M3_FRACTAL_NUMERICS.md)에서 원본 0 나눗셈·메모리 오류 3종·큰 혼합값의 차이를 재현하고 보완했사와요. 정상 네이티브 시나리오 3,186종과 Lua 시나리오 18종을 두 최적화 구성에서 대조하며, 오류 거부·작은 rifts·Lua 복구를 포함한 556,730개 검사를 수행하와요. 감사 기록은 `fractal_numeric_component`로 해당 범위를 연결하와요. 산맥 배치 예산 초과는 높이를 보존하되 소비한 난수를 되돌리지 않으므로, 전체 지도 생성 실패 뒤 실행부 세션·난수 복구와 실제 지도 생성은 계속 미해결이랍니다.

GameCalendarUtilities의 선택적 패턴 include, 활성 DLC/시나리오/모드 VFS, UI 스크립트, 원본 VM 공유·include·이벤트 규약도 남아 있사와요. 원본 실행부의 검색 순서와 같은 것으로 추정해 묵인하지 않으며, 이번에 명시한 BNW 파일 선택을 전체 모드 호환성으로 표시하지 않사와요.
