# 도시 AI 전략 소유 객체 정리

2026-09-26 / CvGlobals::uninit()의 도시 AI 전략 보관 객체 해제 누락을 수정했사와요. 기존 552개 패치를 그대로 보존하고 종료 코드 한 곳에 SAFE_DELETE(m_pAICityStrategies)를 추가한 553개 패치랍니다.

현재 후속 attempt_025는 556개 패치·SDK 수정 파일 94개이며 게임·지도 생성 실패 정리까지 포함하와요. 아래 attempt_024와 553개 수치는 이 정리 수정 단계의 기록이랍니다. 도시 AI 정리 시험 23,146개는 현재 빌드에서도 유지했사와요.

## 요구사항과 영향

| 항목 | 계약 |
|---|---|
| 결함 | CvGlobals::init()이 할당하는 전략 보관 객체가 기존 uninit()에서 해제되지 않음 |
| 수정 위치 | 플레이어·팀 정리 뒤, 다른 AI 전략 객체와 함께 해제 |
| 소유권 | 보관 객체 → 전략 항목 → 두 종류의 flavor 배열을 기존 소멸자로 해제하고 소유 포인터를 null로 변경 |
| 보존 | 클래스 필드·배치·저장 형식·ID·스키마·규칙·효과·밸런스 |
| 배포 범위 | 별도 프로젝트 Source → Build → Stage. 설치 SDK·게임·MODS·저장 파일 변경 없음 |

## 실행 검증

SDK의 CvGlobals::uninit() 전체 본문과 CvAICityStrategies 생성자·소멸자·DeleteArray(), CvAICityStrategyEntry 소멸자 본문을 변경 없이 추출했사와요. 원본과 수정본을 별도 AMD64 프로그램으로 컴파일하고 실행했답니다.

보관 객체·항목·배열에는 실제 C++ 할당과 삭제를 사용하와요. 전체 SDK 클래스 대신 필요한 필드를 가진 시험 클래스 선언을 사용하며, 나머지 전역 소유 객체·플레이어·팀·호스트·DB 조회는 관측 가능한 대체물로 구성했사와요. 배열 삭제 매크로와 클래스 저장소 해제에 계측을 넣어 순서·횟수를 확인하와요.

| 검증 | 결과 |
|---|---|
| 상태 조합 | 원본·수정본 각각 132개 |
| 입력 경계 | null 보관 객체, 항목 0·1·5·32개, 두 배열 각각 존재/부재, null 항목, 미리 비운 목록과 재차 비우기 |
| 외부 경계 | 호스트 유무, 나머지 전역 소유 객체의 할당 유무 |
| 원본 관측 | 보관 객체 128개·항목 608개·배열 608개가 종료 본문 실행 후 잔존; 관측 후 시험 자체가 별도 정리 |
| 수정본 관측 | 모든 조합에서 전략 소유 객체·항목·배열 잔존 0, 각 저장소 한 번 해제 |
| 순서 | 플레이어 → 팀 → 전략 보관 객체 → 조회 정리 → 선택적 호스트 종료 → 경로 탐색기 정리 |
| 검사 수 | 원본 11,542개, 수정본 11,604개; 합계 23,146개 |
| 빌드 | 두 독립 시험 모두 x64 /MD /W4 /WX, 경고 0 |
| 실행 의존성 | Windows/CRT만 허용하는 import 검사 후 실행, GameCore DLL 로드 없음 |

이 시험에서는 uninit()을 조합마다 한 번 호출하와요. 전략 목록의 DeleteArray() 재호출은 검증했지만 전체 GC.init/uninit의 중복 호출·부분 초기화 복구·실게임 수명을 검증한 것은 아니랍니다. 전략 항목의 다른 기반 클래스나 실제 플레이어·팀 소멸자의 동작도 이번 격리 시험의 범위 밖이랍니다.
