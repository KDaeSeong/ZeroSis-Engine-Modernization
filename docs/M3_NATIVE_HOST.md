# 새 64비트 실행부

실제 SDK 인터페이스를 사용하는 x64 실행부 후보를 빌드했사와요. 전용 캐시·규칙 DB·현지화·GameCore 문맥의 연결과 종료 경로를 구현했으며, **실행부 구성요소 시험에 이어 실제 GameCore 초기화·SDK Lua 등록·선택된 조회·종료와 DLL 해제를 영어·한국어에서 통과했사와요. 새 게임·지도 생성·턴 진행은 아직 남아 있답니다.** [실제 실행의 정확한 범위](M3_ACTUAL_CORE_RUNTIME.md)

| 요구사항 | 수용 기준 |
|---|---|
| H01 | 실제 SDK의 EngineUtility4·UserInterface2·GameContext3 선언으로 x64 실행 파일 컴파일; 공개 인터페이스 슬롯 변경 없음 |
| H02 | 구현한 서비스와 미구현 서비스를 구분하고, 미구현 호출은 인터페이스·메서드 이름을 포함해 실패 |
| H03 | GameCore가 생성 중 사용하는 저장 DB는 실행부 전용 새 세션 캐시에 위치 |
| H04 | 실제 재귀 잠금·소유 스레드·진입/실행 상태를 제공; 빈 잠금 함수 사용 금지 |
| H05 | DB·현지화·호스트 어댑터·GameCore 문맥을 의존 순서대로 연결·정리하고 정리 실패 중 DLL 해제 금지 |
| H06 | 실행 파일 자체와 모든 로드 대상의 빌드·해시·아키텍처 및 지원 서비스 목록을 기록 |

배포 범위는 별도 프로젝트의 Source → Build → Stage이와요. 기존 설치 SDK·게임·MODS·저장 파일을 변경하지 않으며, GameCore의 Mod ID·버전·저장 스키마·규칙·밸런스는 변경하지 않사와요. 이번 실행부 구현으로 기존 게임과 동등한 새 게임·턴·저장·멀티코어 성능이 검증되었다고 표시하지 않사와요.

구성요소 검사와 실제 DLL 실행을 별도로 기록하와요. 기존 독립 검사의 문맥은 계측 대체물이며, 새 실제 실행 근거는 `evidence/host_runtime`에 있사와요. 엔진 개조·진행 요청의 개발 검증 범위에서 새 시험 폴더의 실제 DLL을 실행했으며 기존 게임 실행파일과 사용자 저장 파일을 사용하지 않았답니다.

## 구현과 소유권

- `Source/Host/HostMain.cpp`: 기능 안내·묶음 검증·데이터 점검·실제 초기화 명령을 분리하와요. `--initialize <언어>`와 `--check-core <언어>`는 실제 DLL을 불러오며, 후자는 Lua 조회와 종료 뒤 참조 검사를 더하와요. 실제 영어·한국어 실행 기록이 있답니다.
- `CoreRuntimeProbe.h`: 실제 SDK가 등록한 플레이어/팀·지도·게임·타입 조회와, 전역 객체 종료 뒤 남은 참조 거부를 검사하와요. 생성 전 지도와 턴을 읽는 범위이며 새 게임을 진행하는 기능은 아니랍니다.
- `HostRun.h`: 검증된 데이터의 새 세션 사본과 작업 폴더를 만들고 DB·현지화·실행부·GameCore를 의존 순서대로 정리하와요. 종료 실패 시 전체 소유 객체를 유지하고 오류로 종료하므로 정리 대기 중 모듈을 해제하지 않사와요.
- `GameCoreSession.h`: 시작 실패 정리, 완료한 정리 단계의 중복 방지, 실패한 단계의 재시도, 재진입·동시 변경·다른 소유 스레드의 종료를 거부하와요. 컨텍스트는 DLL 소유 차용 포인터이며 종료 중 삭제될 수 있으므로 bootstrap 종료 재시도에서 다시 접근하지 않사와요.
- `HostServices.h`: 실제 재귀 잠금·소유 스레드·실행 횟수·공유 상태와 UI 변경 표를 구현하와요. 인터페이스 조회마다 독립 어댑터를 소유하고 세션 상태를 공유하며 SDK의 `Destroy` 경계에서 해제하와요. 새 전역 상태를 시작할 때 UI·선택 횟수·종료 표시·누락 음향 기록을 초기화하며 다른 스레드의 전역 시작·종료를 거부하와요.
- `ScriptSystem.h`·`ScriptArguments.h`: 실제 Lua 5.1 제공자와 SDK의 13개 메서드, 길이 지정 인수와 GameEvents 전달·오류 복구·VM 수명을 구현하와요. 종료한 서비스는 다시 열지 않으며 원본 이벤트 의미와 실제 게임 라이브러리 실행은 후속 검증 범위랍니다. 게임 라이브러리 바인딩과 설치된 기본 지도/게임플레이 자료 탐색은 [자료 연결 단계](M3_HOST_SCRIPT_ASSETS.md)에서 추가했사와요. [Lua 서비스 검증](M3_HOST_SCRIPT.md)
- 게임 라이브러리를 연결한 VM의 실행·이벤트·등록과 생성/반납/종료에는 게임 소유 스레드와 잠금을 요구하와요. 원본의 잘못된 접근 120건과 잠금 없는 콜백 36회를 재현한 뒤 수정본 검사 1,440개를 통과했답니다. 원시 Lua API 호출자와 실제 GameCore의 객체 수명은 별도 계약이와요. [실행 접근 제어](M3_HOST_SCRIPT_ACCESS.md)
- `HostFailure.h`: 외부 예외의 메시지를 DLL이 살아 있을 때 복사하고, 실행부 소유 오류만 호출자에게 전달하와요. 실제 시험 DLL을 해제한 뒤 원본의 접근 위반 14건을 재현하고 수정본 874개 검사를 통과했답니다. [DLL 예외 수명](M3_HOST_EXCEPTION_BOUNDARY.md)
- `MapSurface.h`·`AudioCatalog.h`: 타일 수에 맞는 불변 지도 표시 상태를 새 세대로 게시하고, 실제 XML에서 만든 환경음 카탈로그를 조회하와요. [지도·음향 계약과 검증](M3_HOST_MAP_AUDIO.md)
- `HostFiles.h`: v3 묶음의 9개 고정 파일 SHA-256과 x64 EXE/DLL 구분을 검사하고 열린 읽기 핸들을 유지하와요. 새 세션은 충돌 없이 만들며 기존 파일을 삭제하지 않사와요.

`ICvEngineUtility4`의 260개 슬롯 중 22개, `ICvUserInterface2`의 152개 슬롯 중 7개를 구현했사와요. 조회·해제 슬롯도 이 수에 포함되며 **총 383개 슬롯은 이름을 명시해 예외로 거부**하와요. 모드 DB는 실제 DB가 지정되어야 사용할 수 있고 이 초기 실행부에는 아직 연결하지 않았답니다. 음향 태그 조회는 환경음 종류에 한정되며 음향 재생·게임 객체/설치 스크립트·네트워크·화면 등의 전체 서비스를 구현한 수치가 아니랍니다. 정확한 목록은 `evidence/host/services.json`에 있사와요.

## 실행 후보와 재현

별도 실행 후보는 `Stage/NativeHost/ZeroSisHost_x64.exe`이며, 같은 폴더의 DLL 3개·DB 2개·ICU 자료·음향/스크립트 카탈로그와 `bundle.manifest`를 사용하와요. 실제 GameCore는 attempt_037의 해시 `637dbad261da632986deed39ac9a442415dbc627eef7de19fe9de01039123d5a`로 추적하와요. [등록 경로의 오류 전달](M3_LUA_REGISTRATION.md)과 [프랙탈 소유권·기본값 수정](M3_LUA_FRACTAL.md), [수치·오류 경계](M3_FRACTAL_NUMERICS.md), [차용 객체의 참조 수명](M3_LUA_BORROWED_OBJECTS.md)을 정식 컴파일·연결에 반영했으며, 이 DLL의 실제 초기화·선택된 Lua 조회·종료를 [별도 실행 기록](M3_ACTUAL_CORE_RUNTIME.md)으로 확인했사와요.

```text
python tools/prepare_host_audio_catalog.py
python tools/prepare_host_script_catalog.py
python tools/build_native_host.py
python tools/prepare_native_host_bundle.py
python tools/verify_native_host.py
python tools/audit_host_script_bindings.py
python tools/native_host_evidence.py
python tools/audit_native_host_services.py
python tools/stage_native_host.py
python tools/verify_project.py
```

실행 파일의 `--capabilities`와 `--verify-bundle`은 세션을 만들지 않사와요. `--check-data ko_KR`와 `--check-data en_US`는 실제 DB·현지화·Lua 제공자와 보유 Continents 지도 정보 함수를 실행하고 `sessions/<고유 ID>/rules.db`만 새로 만들며 GameCore를 불러오지 않사와요. 실제 실행은 `run_gamecore_initialization.py --mode check-core --language ko_KR`처럼 새 복사본에서 기록하와요. `refresh_host_runtime.py`가 두 언어의 현재 실행 근거와 검토 묶음을 갱신하와요.

해시는 현재 묶음의 일관성을 검사하는 수단이며 배포자의 서명을 대신하지 않사와요. Windows는 실행부가 정적으로 가져오는 DB·현지화 DLL을 진입점 전에 불러오므로 이 검증은 불신 코드 실행을 막는 보안 경계가 아니랍니다.

## 남은 관문

실제 Windows DLL 로딩·내보내기 조회·GameCore 시작/종료와 일부 Lua 객체 조회, GameInfo의 12개 규칙 표 조회는 통과했사와요. [GameInfo 구현](M3_HOST_GAME_INFO.md)은 독립 실패·복구 검사 4,026개와 실제 두 언어의 SQL 대조로 추적하와요. 새 게임 설정·지도/도시/유닛 생성·턴·저장·AI 동등성과 게임 계산 병렬화, 전체 자식 객체의 실패 복구는 남아 있답니다. 보유 DB는 이전에 검증한 BNW 캐시 사본이며 현재 모드 조합을 새로 조립한 규칙 DB가 아니랍니다. 실행부의 UI 상태 저장은 렌더링 구현이나 인게임 UI 검증에 해당하지 않사와요.

정적 시작 경로에서 확인한 `DoMapSetup`과 환경음용 `GetAudioTagIndex`를 실제 실행부 상태·자료 조회에 연결했고, 후속 실제 초기화도 통과했사와요. 툰드라 환경음 정의 누락의 기존 실행부 동작, 추가 간접 호출·스크립트·모드 서비스 연결은 남아 있사와요. 정확한 함수 본문·DB 행·호출 위치는 `evidence/host/startup_services.json`에 있으며 이 조사는 전체 간접 호출 그래프가 아니랍니다.
