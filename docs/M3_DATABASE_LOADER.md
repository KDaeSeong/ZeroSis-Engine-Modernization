# DB 로더 소유권과 재시작 캐시

2026-09-26 / 기존 563개 패치를 그대로 보존하고 DB 로더 소유권 패치 5개를 추가했사와요. 정식 attempt_028에서 SDK 수정 파일 95개·지원 헤더 6개·GameCore C++ 161개를 컴파일하고 제공자 16개와 연결해 미해결 0개·AMD64 DLL 생성을 확인했사와요.

## 요구사항과 변경 범위

| 요구사항 | 구현과 수용 기준 |
|---|---|
| DL01 | GC가 보유한 로더 참조 하나를 종료 때 반납하고 캐시된 포인터를 먼저 비움 |
| DL02 | QueryInterface가 호출자에게 준 별도 참조는 GC 참조 반납만으로 소멸시키지 않음 |
| DL03 | 다음 로더 요청은 새 캐시 준비 상태에서 시작하고 변경된 규칙 행을 다시 조회 |
| DL04 | GC.init 이전에 요청한 로더도 컨텍스트 종료 시 호스트·전용 힙 종료 전에 정리 |
| DL05 | 할당 실패 후 재요청과 힙 종료 실패 후 재시도에서 이중 해제·잔존 참조 없음 |

변경 대상은 별도 SDK 이식본의 CvGlobals.cpp·CvGlobals.h·CvDllContext.cpp 세 파일이랍니다. 기존 ZeroSisHostBinding의 살아 있는 ICvUnknown 객체에 대한 Destroy 호출을 재사용하와요. 비가상 도우미 함수만 추가하며 인터페이스 슬롯·객체 필드 배치·저장 형식·규칙·모드 식별자는 바꾸지 않사와요. 설치된 게임·SDK·MODS·저장 파일은 변경하지 않았사와요.

CvGlobals의 정적 싱글턴은 C++ 정적 초기화 규칙으로 포인터가 0에서 시작하와요. 새 도우미는 포인터를 먼저 비우고 소유 참조 하나만 반납하와요. GC.uninit에서는 내부 Defines 조회를 해제한 뒤 호스트 UninitGlobals 전에 호출하며, 컨텍스트 종료에서는 컨텍스트 차용 객체를 정리한 뒤 호스트·전용 힙보다 먼저 호출한답니다.

## 실제 구성요소 실행 결과

시험은 원본 SDK에서 추출한 factory·생성자·소멸자·참조 증감·QueryInterface·캐시·Flush 함수와 실제 수정된 uninit·ShutdownSingleton 본문을 실행하와요. Windows 전용 힙과 기존 검증된 x64 SQLite 제공자를 사용하되, 다른 게임 객체·호스트·규칙 정보 사전 적재 동작은 관측 가능한 대체물로 구성했사와요.

| 시험 | 관측 결과 |
|---|---|
| 원본 종료 | 내부 소유 참조가 남고, 전용 힙 종료 후에도 factory 포인터가 남음; 해제된 포인터를 역참조하지 않음 |
| 원본 캐시 | 규칙 행을 변경한 뒤 다시 요청해도 기존 캐시 준비 상태 때문에 과거 정보를 유지 |
| 수정본 재시작 | 64회 순환에서 수정한 규칙 행을 새 로더가 읽고, 같은 로더의 정상 중복 호출은 재적재하지 않음 |
| 외부 참조 | GC 소유 참조를 반납해도 호출자 참조는 유지되며, 별도 신규 로더와 독립적으로 해제 |
| 초기화 전 요청 | GC.init을 호출하지 않은 로더도 컨텍스트 종료에서 해제 |
| 실패 복구 | 할당 실패 16회·힙 종료 실패 16회 후 재시도 성공 |
| 해제 | 후보 객체 208개가 각각 한 번 해제되고 힙 종료 시 잔존 객체 0개 |
| 검사 수 | 현재 원본 28개 + 수정본 4,180개 = 4,208개 |

시험 프로그램은 /W4 /WX에서 경고 없이 빌드했으며, 실행 전 가져오기 목록에서 GameCore가 연결되지 않았음을 확인했사와요. 원본 비교는 같은 x64 DB 제공자 위에서 SDK 함수 본문을 실행한 결과이며, 원본 Windows 게임 실행 파일의 동작을 측정한 것은 아니랍니다.

## 남은 범위와 회귀 위험

수명 조작은 실행부가 직렬화해야 하며 참조 횟수의 동시 변경을 지원하지 않사와요. 컨텍스트 힙 종료 전에는 외부 호출자의 모든 참조를 반납해야 하와요. 이번 변경이 그 호출자의 작업 중지와 반납을 강제하지는 않사와요. 이전 세대 로더로 다음 게임의 캐시를 조작하는 동작도 지원 범위에 넣지 않사와요.

직접 보유 규칙 정보 정리는 [후속 정리 단계](M3_INFO_CLEANUP.md)에서 보완했사와요. GC.init의 DB 실패 검사와 지역 로더 참조 반납은 [DB 캐시 단계](M3_DATABASE_CACHE.md)에서 보완했사와요. 플레이어·팀 부분 생성 복구와 중복 초기화 방지는 남아 있답니다. 캐시의 중복 진단 단언 제거로 최신 검사 수가 4,432개에서 4,208개로 바뀌었으며, 재시작·참조·할당 실패·힙 종료 실패 시나리오는 그대로 통과했사와요. GC.init 전체 성공·실패·재시작이나 GameCore DLL 로딩·새 게임·턴 진행·게임 멀티코어가 검증됐다고 표시하지 않사와요.
