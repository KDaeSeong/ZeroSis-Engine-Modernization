# 프랙탈 수치 입력과 유한한 산맥 생성

현재 attempt_036의 GameCore 161개 컴파일과 제공자 16개 연결을 통과했으며, 미해결 심볼은 0개랍니다. 기존 620개에 9개를 추가한 합계 629개 패치·SDK 수정 파일 104개·지원 헤더 10개이와요. DLL SHA-256은 `c6ee2a88a68f6baf270910cff04406555db9d45e69e2caa731ebd9e1c64432ad`이며, 기존 컴파일 경고는 343개 위치로 같사와요. 실제 GameCore는 불러오지 않았답니다.

## 요구사항과 영향 범위

정식 기준은 attempt_035의 620개 패치랍니다. 새 수정은 별도 후보에서 원본 계산과 비교한 뒤 정식 SDK·DLL에 통합하와요. 대상은 `CvFractal.cpp`·지수 설명 한 줄과 Lua 오류 전달 경계이며, 객체 배치·저장 필드·모드 ID·버전·기존 규칙은 유지하와요. 설치 SDK·게임·MODS·저장은 변경하지 않사와요.

| 요구사항 | 수용 기준 |
|---|---|
| FN01 | 출력 폭·높이의 양수 여부와 내부 지수를 네이티브 경계에서 검사하며 잘못된 입력은 기존 프랙탈·난수 변경 전에 거부 |
| FN02 | 음수 지수의 기존 기본값 의미, 모든 정수 grain의 포화 의미, 유효 출력 좌표·백분위의 기존 계산 보존 |
| FN03 | 힌트 길이와 입력 rifts의 초기화·실제 읽는 격자 범위를 검사하고 작은 격자의 반복 감김을 안전하게 처리 |
| FN04 | 음수 혼합값·불가능한 시드 수·미초기화 객체를 거부하고, 큰 비음수 혼합값의 산술 넘침 제거 |
| FN05 | 산맥 배치에 유한한 재시도 예산을 두고 실패 시 프랙탈 높이를 부분 변경하지 않음 |
| FN06 | 네이티브 예외를 Lua 오류로 바꾸되 C++ catch 범위를 벗어난 뒤 Lua 오류를 발생시키며, VM을 다시 사용할 수 있음 |
| FN07 | 같은 정상 입력에서 원본과 수정본의 높이·난수 시드·호출 수·범위/반환 기록 일치, 수치 오류 시험과 전체 GameCore 실행 범위를 구분 |

출력 폭·높이는 양수 `int` 범위를 허용하와요. 내부 배열은 각 축에 256칸이며 알고리즘이 끝점까지 저장하므로 내부 지수는 0~7을 허용하와요. 음수 지수는 기존처럼 기본 7/6으로 해석하와요. 출력 해상도와 내부 격자를 혼동하여 출력 지도에 임의의 254칸 상한을 새로 씌우지 않사와요.

grain은 뺄셈 전에 구간을 비교하여 기존 포화 계산을 유지하와요. 힌트 포인터가 있으면 계산된 정확한 길이를 요구하되 호출자가 넘긴 실제 메모리 할당 크기까지 이 API가 증명하지는 않사와요. rifts는 실제 읽는 내부 열·행을 포함하고 초기화가 완료되어야 하며 자기 자신을 초기화 입력으로 쓰는 것은 거부하와요. 내부 격자가 작은 경우 감김은 나머지 연산으로 처리하와요.

산맥 혼합값은 비음수 정수를 허용하고, 둘 다 0일 때 기존의 높이 0 결과를 유지하와요. 곱셈·합은 64비트로 계산하와요. 시드 수가 3보다 작은 입력은 기존처럼 3으로 올리며, 서로 다른 좌표를 놓을 수 있는 보수적 상한을 넘으면 난수를 쓰기 전에 거부하와요. 기존 초기 배치와 재배치가 사용하는 서로 다른 좌표 표현은 이번에 바꾸지 않사와요.

산맥의 전체 재배치 예산은 내부 격자 칸 수의 64배에 1,024회를 더한 값이랍니다. 예산 안에서 성공하는 입력은 배치 순서·난수 소비를 유지하며, 초과하면 대체 지형을 만들어 성공으로 보고하지 않고 명시적으로 실패하와요. 실패까지 소비한 난수는 되돌리지 않으며, 높이 배열은 모든 시드 배치가 성공한 뒤에만 수정하와요. 그러므로 호출자가 실패를 잡고 재시도할 때의 난수 진행과 세션 복구는 별도 계약으로 기록하와요.

## 검증과 현재 단계

네이티브 원본·후보 계산과 실제 Lua·FLua를 사용하는 정식 생성 SDK와 같은 본문으로 **556,730개 검사·30개 프로세스**를 통과했사와요. 난수는 원본 수치 연산의 어댑터이며 전체 GameCore의 로그·스레드·게임 소유 서비스를 실행한 것으로 보지 않사와요. 정식 패치 적용·전체 빌드·Stage 갱신과 실제 지도 생성·턴 진행·게임 멀티코어 성능은 각각 별도 관문이랍니다.

| 시험 | 관측과 범위 |
|---|---|
| 정상 네이티브 계산 | 각 구성에서 3,186개 시나리오; 0~7 지수 조합·grain·감김/극지/반전 설정·힌트·rifts·산맥의 표본 높이와 난수 기록이 원본과 일치 |
| 정상 Lua 계산 | 각 구성에서 기존 18개 시나리오의 높이와 난수 기록 일치 |
| 최적화 차이 | 원본과 후보 모두 `/O2`·`/Od`에서 비교 |
| 0 나눗셈 | 원본 폭 0이 두 구성에서 `0xC0000094` 종료; 후보는 기존 상태·난수 변경 전 거부 |
| 메모리 범위 위반 | 원본 내부 지수 8·길이 2 힌트·작은 rifts 격자에서 AddressSanitizer가 실제 heap-buffer-overflow 보고 |
| 사전 검사 | 잘못된 크기·지수·힌트·rifts·혼합값·시드 수 29개 거부, 기존 프랙탈과 난수 유지 |
| 산맥 반복 | 원본의 불가능한 2×2 배치가 추가 난수 20,000회까지 종료하지 않아 시험용 관측 제한에서 중단; 후보는 추가 2,570회 뒤 명시적 예산 오류, 높이 유지 |
| 큰 혼합값 | 원본의 `INT_MAX : INT_MAX`가 같은 비율 1:1과 여섯 경우 모두 달랐고, 후보는 여섯 경우 모두 일치 |
| 작은 격자·극단 정수 | 작은 rifts 16종과 `INT_MIN` grain·출력 크기 `INT_MAX`·반복 감김의 경계 검사 |
| Lua 오류 복구 | 일곱 실패 경로를 pcall로 받고 재생성·기존 객체 조회·VM 종료 성공; 표준/알 수 없는/할당 예외 전달과 예외 객체 소멸 확인 |

메모리 검사는 이 시험 실행 파일의 프랙탈 함수에 적용하와요. 기존 FLua·Foundation 라이브러리와의 STL 설정 일치를 위해 문자열·벡터 컨테이너 주석 기능은 껐으며, 배열·힙 접근 검사는 활성화했사와요. 기존 제공자 전체를 sanitizer로 재빌드한 결과는 아니랍니다. 원본 오류 재현은 예상된 실패로 별도 분류하며, 성공한 수정본 검사와 혼합해서 성공 종료로 세지 않사와요.

원본의 산맥 반복은 실제 게임을 멈춰 관측한 결과가 아니랍니다. 수치 난수 어댑터가 관측 한도에서 예외를 던지도록 하여 독립 프로세스의 끝없는 실행을 막았고, 수정본의 자체 제한이 그 전에 동작함을 확인했사와요. 무효 입력을 고쳐 넣거나 실패한 지도를 다른 지형으로 대체하여 정상 결과로 처리하지 않사와요.
