# 실제 SDK 지도 객체의 x64 생성·변경과 연결 실험

2026-09-25 / `WORLD_BUILDER_MAP_OBJECT_COMPONENT_PASS` / `WORLD_BUILDER_MAP_OBJECT_LINK_EXPERIMENT_PASS`이랍니다. 실제 `CvWorldBuilderMap` 클래스의 구현이며, 이후 파일 연결과 정식 SDK 재빌드까지 진행했사와요. 아래는 객체 구성요소의 계약이며 현재 전체 통합 상태는 [정식 SDK 통합 기록](M2_WORLD_BUILDER_MAP_INTEGRATION.md)에 있사와요.

변경은 이 독립 프로젝트의 Source·Tests·tools·Build·evidence·별도 `Stage/WorldBuilderMapObject`에 한정하와요. 원본 SDK·게임·설치 MODS·저장 파일·Mod ID·버전·스키마·밸런스를 변경하지 않았사와요. SDK 접근 선언 2개는 격리된 헤더 사본의 풀과 핸들에만 추가했으며, 필드·가상 함수·공개 서명·메모리 배치를 바꾸지 않았답니다.

## 원본에서 확인한 동작

- `Resize`는 크기 값만 변경하와요. 기존 타일을 행별로 재배치하지 않고, 축소로 숨겨진 지형·시나리오·부가 데이터도 유지하와요. 크기를 다시 늘리면 그대로 드러난답니다. 부가 데이터 개수 조절은 별도 API 계약이와요.
- `SetAllPlotData`는 현재 지도 범위에만 적용하와요. 인수가 기존 타일을 가리키더라도 값 복사 후 적용하와요.
- 시나리오 초기화는 기본 게임 설명·가시성·영향력·그룹·도시/유닛/이름 풀을 초기화하와요. 지도 이름·설명·월드 종류·지형·부가 데이터·플레이어/팀 슬롯·외교 관계 비트는 유지하와요. 개선 시설 보존 옵션은 개선 시설에만 적용하고 도로·소유권은 초기화하와요.
- 플레이어와 도시 국가 교환은 활성 범위의 영향력과 타일에서 도달 가능한 소유권만 교환하와요. 연결되지 않은 할당 슬롯과 비활성 영향력은 건드리지 않사와요. 팀 관계와 플레이어의 팀 번호는 슬롯 내용과 함께 원본 의미를 유지하와요.
- 유닛은 타일 스택의 앞에 추가하고, 제거한 핸들은 무효화하와요. 사용자 이름 슬롯은 원본처럼 유지하와요.
- 원본의 `OldCity`→`City`, `OldPlayer`→`Player` 변환은 각각 구형 건물/정책 비트를 지우며, V2 변환은 256개 비트를 512개 공간에 보존하와요. 관측한 변환 의미를 유지했사와요. 파일 버전별 변환 흐름 자체의 통합은 아직 남아 있답니다.
- `UnitV2`→`Unit`은 원본처럼 사용자 이름 참조를 무효화하와요. 실제 할당한 이름 핸들 0을 넣어 원본 출력 `V2-NAME|0|65535`를 확인했으며, 구형 파일의 이름 풀 자체는 보존하는 별도 계약이랍니다.

원본 유닛/도시/플레이어/팀의 네이티브 크기는 84/136/436/64바이트이고 x64는 88/136/440/64바이트랍니다. 비교 도구는 풀의 네이티브 바이트 수를 슬롯 수로 환산하며, 상태 기록은 고정 폭 필드와 비트별 값으로 직접 비교하와요. 이 객체의 `Serialize` 풀 메모리를 지도 파일에 그대로 쓰면 호환되지 않으므로, 후속 파일 연결에서는 이미 구현한 명시적 wire 형식을 사용해야 하와요.

## 재현한 결함과 보완

원본에서 4×3 지도에 유닛과 도시를 놓고 1×1로 줄인 뒤 시나리오를 초기화하고 다시 4×3으로 늘렸사와요. 원본은 두 풀의 크기가 0인데도 숨겨진 타일의 유닛·도시 핸들 0을 그대로 반환했답니다. 원본의 해제된 객체를 역참조하지 않고 핸들 값과 풀 크기로 결함을 재현했사와요.

새 구현은 풀 해제 시 비활성 타일의 유닛·도시 참조도 무효화하와요. 비활성 타일의 나머지 값은 보존하와요. 이 사례만 `HIDDEN-HANDLES|0|0|0|0`→`HIDDEN-HANDLES|65535|65535|0|0`이라는 명시적 차이로 기록했으며, 정상 조작의 25개 상태 기록에는 차이가 없사와요.

추가 방어 계약은 다음과 같답니다.

- 지도 크기와 곱이 고정 저장 공간 32,768타일을 넘으면 기존 크기를 유지하며 예외를 반환하와요.
- 고정 문자열은 63바이트까지 허용하고 NULL·길이 초과는 변경 전에 거부하와요. 내부 문자열을 다시 인수로 전달하는 경우도 지원하와요.
- 유닛 스택의 순환·이미 해제된 슬롯·여러 타일의 중복 소유·잘못된 플레이어 교환은 변경 전에 거부하와요. 유닛 제거의 출력 인수가 내부 스택 연결 자체를 가리키는 경우도 거부하와요.
- `AddUnit` 경로는 풀 증가를 65,535슬롯에서 제한하여 16비트 핸들이 잘리는 것을 방지하와요. 한계 뒤 추가 실패와 반환된 슬롯 재사용을 검증했사와요.
- 구형 레코드 변환에서 끝 문자가 없는 이름·16비트 인구 범위 초과·음수/비유한/32비트 범위 초과 체력은 명시적으로 거부하와요. 최대 체력보다 큰 값도 정수 필드 범위 안이면 보존하와요.

## 실행 검증과 연결 실험

원본과 후보의 조작 모드 11종은 정상 10종과 위 결함 재현 1종으로 나뉘며, 원본 아카이브와 새 구현이 각각 실행했사와요. 정확한 상태 기록은 25개·66,867바이트랍니다. 후보의 제품 오브젝트와 두 소비 프로그램은 `/MD /W4 /WX`로 경고 없이 빌드했사와요. 원본에는 기존 SDK 헤더의 인코딩 경고가 남아 있답니다.

후보의 실패 검사는 C++ 할당 실패 24건과 성공 재시도 4건에서 공개 상태 기록과 유닛·도시·이름 풀 바이트를 보존하고, 대체 `new/delete`로 추적한 생존 할당 수가 복구됨을 확인했사와요. 작업자 4개에서 독립 지도 256개·유닛 2,048개를 생성·교환·제거했답니다. 같은 지도에 대한 동시 변경이나 실제 게임 병렬 계산의 시험은 아니와요.

연결 실험은 기존 GameCore 오브젝트 161개와 제공자 목록으로 누락 17개를 먼저 재현하고, 새 지도 객체 라이브러리만 더하여 7개로 줄였사와요. 생성·소멸·초기화·크기 변경·월드 종류·플레이어 교환과 오류 반환용 정적 객체 4개, 합계 10개가 해소되었답니다. 남은 항목은 지도 `Load`, `Save`, `PreviewPlayableCivCount`와 파일·로그·디버그 서비스 4개랍니다. 두 실행 모두 링크 실패 상태이며 GameCore DLL은 생성·로드하지 않았사와요.

## 남은 통합과 회귀 범위

1. 파일 문서와 실제 객체 사이의 버전별 타입·핸들·풀·관계·가시성 변환, 실패 시 전체 상태 보존, `Load/Save/Preview` 구현이 남아 있사와요.
2. 접근 선언을 정식 SDK 패치 계획에 통합하고 모든 관련 번역 단위를 같은 헤더로 다시 빌드해야 하와요. 이번 연결 실험은 기존 오브젝트에 대한 심볼 해소 관측이며 이 전체 재빌드를 대체하지 않사와요.
3. SDK 공개 풀의 직접 `Alloc/Free/Deserialize/ConvertTo`는 별도 보완 대상이랍니다. 이번 한계 보호는 지도 메서드 경로에 한정되며, 재사용된 인덱스의 외부 낡은 별칭을 구분하는 세대 식별자도 추가하지 않았사와요.
4. 실제 풀 증가의 C `malloc` 실패 주입은 아직 하지 않았사와요. 이번 실패 주입은 변경 전 검증·준비 과정의 C++ `new`에 한정하와요.
5. 파일·호스트·전체 GameCore 초기화, 전체 저장·모드·실게임·멀티코어 성능은 여전히 미검증이랍니다.
