# 실제 자동 기록 변수의 수명·이름·변경 실패 처리

2026-09-24 / x64 SDK 헤더 수정과 실제 네이티브 구성요소 회귀 검증이와요.

**변수가 소멸하거나 생성 중 실패할 때 등록을 정리하고, 중간 삭제·동시 최초 등록에도 변수 이름을 보존하도록 고쳤사와요.** 벡터의 범위 오류와 변경 중 메모리·값 연산 실패도 처리했답니다. 수정한 SDK로 GameCore C++ 161개를 다시 컴파일했고, 실제 링크의 미해결 심볼 집합은 113개로 유지되었사와요. 이 작업은 게임 전체의 실행·저장 호환성·멀티코어 성능 관문을 통과했다는 뜻은 아니랍니다.

## 요구사항·변경 범위·ABI 이전

기존 x64 패치 458개를 기준으로 새 호출부 패치 21개를 추가하여 총 479개가 되었사와요. 이전 패치 내용은 그대로 보존하며, 생성기를 두 번 다시 실행해 패치 계획과 숫자 수정 기록의 내용이 동일함을 확인했답니다. SDK 이식본의 수정 파일은 57→60개, 지원 헤더는 3→4개이며 전체 빌드 기록은 `attempt_014`랍니다.

| 영향 모듈 | 변경 |
|---|---|
| `FAutoVariableBase.h`·제공자 | 등록 소유자와 안정적인 이름 포인터 추가; 기본 클래스가 소멸·부분 생성 실패의 등록 해제를 담당 |
| `FAutoArchiveClassContainer.h` | 등록 순서 번호로 이름을 찾던 공유 map 제거; 변수에 묶인 불변 이름 조회 |
| `FAutoVariable.h` | 소멸 정리를 기본 클래스로 일원화하고 분리된 변수의 이름 조회를 거부 |
| `FAutoVector.h` | 벡터 소멸 자동 해제, 생성 크기·읽기/변경 인덱스 검사, 값과 변경 기록의 준비 후 반영 |
| `CvAutoArchiveSupport.h` | 잠금으로 보호한 불변 이름 저장소, 크기 검사·증가 예약·벡터 변경 준비 도구 |
| 연결·검증·Stage | 모든 컴파일 입력·지원 헤더의 현재 해시 확인, 새 실패·동시성 시험과 산출물 연결 |

**독립 x64 이식본의 내부 메모리 배치를 이전하는 변경**이와요. FINAL_RELEASE의 기본 변수는 8→24바이트, `int` 변수는 24→40바이트, `vector<int>` 변수는 64→80바이트이며 변수당 포인터 두 개가 추가되었사와요. 추가 메모리 비용은 명시적으로 수용한 구현 선택이며 게임 전체의 메모리 사용량 측정은 아직 남아 있답니다.

이전 배치로 컴파일한 GameCore·호스트·제공자를 새 배치와 혼용하면 안 되므로 161개 GameCore 오브젝트와 해당 제공자를 모두 다시 빌드했사와요. 연결 도구는 패치·지원 헤더·전체 이식 소스가 컴파일 당시 해시와 다르면 먼저 거부하와요. 후속 새 호스트도 같은 헤더·컴파일 계약으로 빌드해야 하와요.

두 포인터는 저장하지 않으며, 기존 uint32 번호·목록 길이·값 기록 형식은 그대로랍니다. Mod ID·버전·저장 키·스키마·밸런스·기존 게임 설치 파일은 변경하지 않았사와요. 산출물은 독립 Source → Build → Stage 범위랍니다.

## 수명과 이름의 계약

기본 변수는 등록 소유자를 기억하고 소멸할 때 등록·변경 목록을 함께 제거하와요. 따라서 별도 소멸자가 없는 SDK 벡터 특수화와, 값 생성자가 실패해 파생 생성이 끝나지 못한 경우에도 정리가 적용되와요. 이미 다른 소유자에 등록된 변수의 재등록은 거부하와요.

아카이브가 먼저 소멸할 때는 아직 등록된 변수의 소유자 포인터를 분리하와요. 소유자의 페이지를 실제로 접근 불가로 바꾼 뒤 남은 스칼라·벡터를 소멸시키는 시험이 통과했답니다. **분리된 변수의 나머지 API를 계속 사용하는 계약까지 제공하는 것은 아니며**, 변수 사용은 정상적인 소유자 수명 안에서 이루어져야 하와요.

이름 문자열은 중복을 공유하는 불변 저장소에 보관하고, 삽입·검색 구간을 mutex로 보호하와요. 문자열의 주소는 다른 이름을 삽입하거나 변수를 삭제해도 유지되므로 조회 시 공유 map을 순회하지 않사와요. 최초 생성은 C++14의 지역 정적 초기화로 보호하와요. 같은 변수에 같은 이름을 다시 설정하는 동작은 허용하며, 다른 이름으로 바꾸려는 호출은 거부하와요.

기존 보호 메서드 `getNames()`를 통해 수정 가능한 map을 반환하던 경로는 제거했사와요. 원본 SDK 전체의 검색 결과 이 메서드의 선언·정의·호출 네 곳이 모두 `FAutoArchiveClassContainer.h` 안에 있음을 확인했답니다. 외부 소스가 이 보호 메서드에 의존했다면 새 헤더 계약에 맞춰 수정해야 하와요.

이름 저장소는 서로 다른 이름마다 문자열을 한 번 보관하며 모듈 수명 동안 유지하와요. 모듈 언로드 뒤 이름 포인터 사용은 지원하지 않사와요. 아카이브 자체의 값·등록·변경 목록은 여전히 소유 스레드에서 비재진입 방식으로 다루어야 하와요.

## 벡터 변경과 실패의 계약

일반 변경은 범위·직렬화 크기를 먼저 검사하고, 필요한 값·변경 기록·공간을 준비한 뒤 변경 목록에 표시하고 반영하와요. 실패하면 기존 값, 기존 변경 기록, 기존 변경 대상 목록을 보존하와요. 준비 과정에서 용량이 늘어났거나 입력 스트림이 소비된 사실까지 되돌리는 계약은 아니랍니다.

복사·대입·기본 생성·소멸이 예외를 던지지 않는 원소는 공간을 미리 확보하여 직접 변경하와요. `int`·`bool`이 이 경로를 사용하며, 값이 실패할 수 있는 원소는 별도 값과 명령 목록에서 준비한 뒤 교환하와요. 용량은 여유를 두어 늘리므로 매번 전체 벡터를 복사하거나 원소 하나마다 재할당하지 않사와요.

대입은 입력이 자기 자신의 읽기 전용 뷰인 경우도 처리하와요. 원소 참조를 인수로 받아 내부 재할당이 일어나도 유효한 값을 유지하도록 명령에 먼저 복사하와요. 전체/차등 읽기는 임시 벡터를 완성한 뒤 반영하여 잘린 입력이 기존 벡터를 일부 지우거나 바꾸지 못하도록 했답니다. 성공한 전체 읽기의 변경 표시, 차등 읽기의 기존 변경 표시 유지 등은 원본 의미를 보존하와요.

이 보장은 벡터 변수 한 개의 변경 범위랍니다. 아카이브의 앞 변수를 이미 읽은 뒤 뒤 변수가 실패하는 전체 상태 복구, 임의 스칼라 타입의 대입 실패 복구, 임의 콜백의 부작용 취소는 아직 별도 관문이와요. 원소의 소멸자가 예외를 던지는 비정상 타입도 지원 계약에 포함하지 않사와요.

## 검증 근거

시험은 생성된 SDK 헤더를 그대로 포함하고 새 제공자 라이브러리를 연결한 x64 실행 파일을 사용했사와요. 할당 실패용 `operator new`가 시험 오브젝트에서 연결됨을 링크 지도에서 확인했으며, 직접 DLL 의존성을 확인한 뒤 독립 실행했답니다. 실제 게임이나 GameCore DLL을 로드하지 않았사와요.

| 생성·이름 실패 | 파생 생성·이름 변경/분리 실패 15건, 등록/이름 할당 실패 3건 처리 |
| 수명 정리 | 21개 정리 경로, 소유자 접근 불가 페이지 1개에서 남은 변수 소멸 통과 |

8개 작업자의 시험은 **독립 소유자와 공유 이름 저장소**를 다루와요. 같은 아카이브를 여러 작업자가 수정하거나 실제 게임 턴을 병렬 처리한 증거로 확대하지 않사와요. 41회 할당은 반복적인 전체 복사를 방지하는 경로의 검사이며 실제 게임 속도 향상 수치가 아니랍니다.

## 남은 엔진 관문

데이터베이스·지도 편집 자료·현지화·문자열·Lua 보조 함수·파일/로그 등 113개 연결 요구사항과 새 호스트가 남아 있사와요. 같은 아카이브에 대한 동시 수정, 전체 상태의 원자적 읽기/복구, 저장/멀티플레이 결정성, 실게임 UI·턴·저장/불러오기·새 로그·실제 코어별 성능은 여전히 별도 관문이랍니다.
