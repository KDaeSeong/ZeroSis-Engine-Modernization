# Lua 값·표·보호 호출의 x64 연결

2026-09-24: 실제 GameCore 연결에서 Lua C++ 연결부의 미해결 항목 8개를 해결하여 전체 항목을 **72→64개**로 줄였사와요. 새 오류는 없으며, GameCore DLL 생성과 게임 실행은 아직 미완료랍니다.

## 요구사항과 범위

이번 변경은 별도 프로젝트의 `Source/Providers/FLua`, 네이티브 시험, 연결·검증·Stage 도구에 한정하와요. 현재 GameCore가 요구하는 값 생성·해제·교체·밀어넣기, 표 밀어넣기, 오류 보고, 보호된 C 콜백을 실제 동작으로 제공하와요. 값 복사·자기 대입·교환·형식 조회와 SDK의 표 필드 템플릿도 함께 검증했답니다. SDK 헤더·게임 객체 배치·저장 필드·모드 식별자·밸런스는 바꾸지 않았사와요.

실제 원본 `FLuaWin32.lib`와 `FireWorksWin32.lib`를 VC9 x86 프로그램에 연결하고, 원본 Lua DLL의 복사본을 사용했사와요. x64 제공자는 기존에 검증한 Lua 런타임과 Foundation 잠금을 사용하며, 연결 지도에서 원본 아카이브 코드와 새 구현의 출처를 각각 확인했답니다. 게임 DLL은 어느 시험에서도 로드하지 않았사와요.

## 보존한 동작과 보완

- nil은 유효한 Lua 참조이며 기본 생성된 무효 값과 구분하와요. 원본의 `Invalid` 형식 이름, 빈 값의 nil 판정, 스택 높이와 자료형별 값을 보존하와요.
- 값 복사는 같은 Lua 값을 별도 참조로 보관하와요. 원래 값의 해제가 복사본까지 지우지 않으며, VM 종료 뒤에는 각 값에 `LuaStateDestroyed()`를 통지해야 하와요.
- 표의 값 키 대입은 원시 쓰기이고 이름 대입은 `__newindex`를 거치는 원본 SDK 템플릿의 차이를 보존하와요. nil 키와 다른 VM의 키에 대한 오류도 원본과 같답니다.
- 원본 자기 대입은 참조를 먼저 지워 무효 값이 되는 결함을 실제 실행에서 확인했사와요. 새 구현은 자기 대입을 그대로 유지하며 일반 대입은 후보 값을 먼저 준비해 교체하와요. 내부 참조 번호의 재사용 순서까지 같다고 주장하지는 않사와요.
- 잘못된 일반·내부 인덱스, 호출 문맥이 없는 환경·upvalue 인덱스와 null VM은 기존 값을 바꾸기 전에 거부하와요. 실제 C 함수 안의 유효한 환경·upvalue는 원본과 동일하게 읽었답니다.
- 보호 호출은 원본과 같은 공유 재귀 잠금 아래 실행하와요. C++ 콜백 예외는 C++ 소멸을 마친 뒤 Lua 오류로 전달하며, 오류 처리기가 예외를 던져도 스택과 잠금을 복구하와요. 문자열이 아닌 Lua 오류도 처리하와요.
- 오류 문자열은 원본의 1,024바이트 고정 버퍼 대신 필요한 크기로 구성하와요. 16,384바이트 인수를 포함한 오류를 잘림 없이 전달했답니다. 콜백에서 잡은 C++ 예외 설명은 별도의 1,024바이트 버퍼에 제한하와요.

## 실행 근거

| 관문 | 실제 결과 |
|---|---|
| 원본과 후보의 동일 소스 시험 | 값·표·수명·보호 호출·동시 호출 5종의 기록 완전 일치 |
| 값과 표 | 값 13개와 유효한 내부 인덱스, 아키텍처별 필드 쓰기 4,096회, 참조 복사·GC 수명·VM 종료 통지 |
| 공유 VM 호출 | 작업자 1·2·4·8개에서 합계 7,680회 갱신, 결과 손실 없음; 공유 잠금으로 직렬 실행 |
| 후보 보완 | 잘못된 입력 8건, 자기 대입, 긴 오류, C++ 콜백 소멸, 오류 처리기 예외, 비문자열 오류 |
| 부족 경로 | 보호 호출 진입의 Lua 할당 한 건을 실패시킨 뒤 오류 보고·스택·잠금·다음 호출 복구 |
| 구현과 빌드 | AMD64 실제 구현 오브젝트 1개; 후보와 시험은 `/MD /W4 /WX`, SDK 외부 헤더는 별도 취급 |
| 실제 GameCore 연결 | 대상 8개 모두 실제 구현으로 해결, 추가 오류 0개, 전체 미해결 64개 |

원본 시험 빌드는 기존 SDK 스트림 헤더의 C4819 경고를 기록하와요. 후보의 자체 소스와 시험은 경고 없이 빌드했으며, 전체 GameCore의 잔여 경고 343개 위치와는 별개랍니다.

## 남은 관문

FLua의 모든 공개 API, 실제 엔진 스크립트 호스트·이벤트·게임 객체 수명, VM 종료 통지의 전체 호출부, Lua 할당 실패 전수와 저장·난수·모드 계약은 아직 별도 작업이랍니다. 특히 Lua의 C 오류 점프는 콜백 안의 임의 C++ 소멸자를 실행하지 않으므로, Lua 오류를 가로지르는 모든 값 참조·게임 상태의 정리까지 보증하지 않사와요. 같은 VM을 직접 사용하는 다른 API와 오류 처리기 설정은 호출자가 직렬화해야 하와요. 전역 잠금의 동시 호출 시험은 게임 계산의 병렬 실행이나 속도 개선의 증거가 아니랍니다.

재현 순서는 `build_flua_provider.py --vs <VS 경로>`, `verify_flua_provider.py`, 기존 연결 명령에 `--flua-provider evidence/flua/build_result.json` 추가, Stage, 전체 정합성 검사랍니다. 증거는 `evidence/flua/build_result.json`, `conformance.json`, `link_delta.json`과 원본/후보 실행 로그에 있으며, 배포 범위는 별도 `Stage/GameCore_x64/Providers/FLua` 검토 묶음이랍니다.
