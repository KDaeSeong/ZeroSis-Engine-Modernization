# 규칙 정보 소유권과 부분 적재 정리

2026-09-26 / 기존 568개 패치를 보존하고 규칙 정보 정리·임시 객체 소유권 패치 4개를 추가했사와요. 정식 attempt_029에서 SDK 수정 파일 96개·지원 헤더 6개·161개 GameCore C++ 소스를 재컴파일하고, 제공자 16개와 연결하여 미해결 0개·AMD64 DLL 생성을 확인했사와요.

## 요구사항과 변경

| 요구사항 | 변경과 수용 기준 |
|---|---|
| IC01 | 플레이어·팀·게임·지도·호스트·경로 탐색기의 기존 정리 뒤 규칙 정보 해제 |
| IC02 | CvGlobals가 직접 보유하는 포인터 목록 40개와 문자열 배열 2개 정리 |
| IC03 | 이름·해시 조회표 항목, 성향·발소리·플레이 가능 문명 개수 초기화 |
| IC04 | 적재 중 객체를 목록에 등록하기 전까지 지역 소유자가 보유하고 예외 시 해제 |
| IC05 | 부분 적재·반복 정리·다른 인스턴스의 배열·실패 후 재시도 검증 |

별도 이식본 CvGlobals.cpp와 CvDllDatabaseUtility.h를 변경했사와요. 기존 uninit의 정리 순서를 유지하고 마지막에 deleteInfoArrays를 호출하와요. 기존 정리 도우미에 빠진 부대 편성 목록과 AI 성향 이름 배열을 추가하고, 발소리 배열은 호출받은 객체의 필드를 직접 정리하도록 고쳤사와요. 정보 목록을 지운 뒤 이름·해시 조회표와 관련 개수도 비운답니다.

PrefetchCollection은 생성한 항목을 지역 unique_ptr가 보유하고 목록 삽입이 성공한 뒤 소유권을 넘기와요. CacheResults 또는 목록 확장이 예외를 던지면 미등록 항목이 정리되며 원래 예외가 전달된답니다. 앞서 등록한 항목은 호출자가 정리할 수 있도록 목록에 남기와요. 이 단계에서는 정상 순서·빈 ID 칸·함수의 기존 반환값 의미를 유지했사와요. 후속 DB 캐시 단계에서 실패 반환값 처리를 보완했답니다.

객체 필드 배치·인터페이스·규칙 효과·저장 형식·모드 ID와 버전은 변경하지 않았사와요. 설치 SDK·게임·MODS·저장 파일도 유지했답니다.

## 검증 결과와 범위

| 검사 | 결과 |
|---|---|
| 원본 종료 | 규칙 객체·문자열 배열·조회표가 그대로 남는 현상 재현 |
| 원본 정리 도우미 | 부대 편성·성향 배열·개수·조회표 누락과 다른 인스턴스의 발소리 배열을 지우는 동작 재현 |
| 수정본 정리 | 목록 적재 0~40개 × 2세대, 합계 82개 상태에서 원소·문자열 배열 정리와 반복 정리 확인 |
| 해제 순서 | 실제 SDK uninit 본문에서 대체 플레이어·팀·소유 객체·호스트·경로 탐색기가 정보 정리보다 먼저 종료 |
| 정상 적재 | 원본·수정본 각각 16회에서 4개 규칙 항목과 ID 빈 칸을 포함한 8칸 배치 기준 통과 |
| 적재 실패 | CacheResults 예외 4건·항목 내부 메모리 부족 4건·목록 등록 메모리 부족 1건 |
| 실패 결과 | 원본의 미등록 객체 누수 9건 재현; 수정본은 미등록 객체 정리·기존 등록 항목 보존·원래 예외 전달·호출자 정리 후 재시도 성공 |
| 합계 | 현재 원본 3,182개 + 수정본 9,557개 = 12,739개 검사 |

시험은 실제 SDK의 uninit·deleteInfoArrays·목록 삭제·조회표 초기화·PrefetchCollection 본문을 추출해 실행하와요. 실제 x64 SQLite 제공자를 사용하며, 정보 항목과 다른 게임 객체는 소유권을 관측하는 대체물로 구성했사와요. /W4 /WX에서 경고 없이 빌드하고 가져오기 목록을 검사한 뒤 실행했답니다.

직접 소유 목록은 CvGlobals.h 선언에서 수집하여 정리 대상과 대조했사와요. 소스의 일부 소멸자와 게임 종료 메서드의 직접 참조도 기록했으며, CvGame::uninit이 승리 정보 개수를 사용하므로 정보 정리를 앞당기지 않았사와요. 이 조사는 모든 상속·멤버 소멸자의 전체 호출 그래프나 실행 증거는 아니랍니다.

## 남은 작업과 회귀 경계

SQL 조회·순회 오류와 CacheResults의 false 반환, GC.init의 DB 반환값 검사·지역 로더 참조 반납은 [후속 DB 캐시 단계](M3_DATABASE_CACHE.md)에서 보완했사와요. 전체 캐시의 원자적 복구·구체 정보 클래스의 생성 도중 누수·플레이어와 팀 부분 생성·전체 GC 상태 관리는 남아 있답니다. 최초 12,924개와 현재 12,739개의 검사 수 차이는 PrefetchCollection의 중복 진단 단언 제거에 따른 것이며, 기존 부분 상태 82개와 적재 실패 9종은 그대로 다시 실행했사와요.

외부 실행부가 빌린 규칙 정보는 uninit 전에 사용을 마쳐야 하와요. 해당 작업 중지를 강제하는 전체 실행부는 아직 없으며, 호스트 종료 콜백 예외와 초기화 실패 전체를 복구했다고 표시하지 않사와요. 벡터·해시 컨테이너가 재사용을 위해 보유하는 용량까지 모두 0으로 만드는 변경도 아니랍니다.

GameCore DLL 로딩·실제 새 게임·턴 진행·저장 호환·멀티코어 계산과 성능은 이번 구성요소 검증에 포함하지 않았사와요.
