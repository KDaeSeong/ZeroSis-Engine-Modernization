# M2: x64 숫자 변환과 입력 경계

> 후속 단계에서 Lua x64 제공자의 실제 x86 동등성을 비교하고 연결 오류 40개를 해소하여 현재 미해결 심볼은 302개랍니다. 숫자 경계값도 실제 /MD 제공자로 재검증했사와요. [최신 Lua 제공자 기록](M2_LUA_PROVIDER.md)

2026-09-24 / attempt_009 기준이랍니다. 기존 /W3에서 관측한 숫자 변환 경고
479곳을 해결하고 실제 BNW C++ 161개를 AMD64 오브젝트로 다시 컴파일했사와요.
전체 엔진의 연결·실행·멀티코어 게임 관문은 계속 진행 중이랍니다.

## 요구사항과 변경 범위

기존 게임의 유효한 정수값, 알림 식별자의 32비트 패턴, 저장 필드 너비를
보존하면서 64비트 계산의 잘못된 축소 변환을 막는 것이 요구사항이와요.
영향 모듈은 BNW Lua, FLua, 컨테이너 개수·변경 명령, 데이터베이스 배열,
팀 배열의 할당 설명자, 구형 알림의 순서→식별자 표랍니다.

숫자 수정 대상은 52개 SDK 파일이며, 이전 이식을 합치면 54개 파일·443개
패치 항목이랍니다. 공통 지원 헤더는 CvCheckedNarrow.h와 CvLuaCheckedInteger.h
두 개이며 C++14로 GameCore와 함께 컴파일하와요. 기존 SDK·게임·설치 MODS·
Mod ID·버전·저장 키·스키마는 바꾸지 않았사와요.

## 구현 계약과 실행 증거

| 항목 | 구현 | 확인한 범위 |
|---|---|---|
| 개수·길이·인덱스 | 대상 정수 범위를 검사한 뒤 변환 | signed/unsigned 64비트 입력과 10개 대상형, 42,250건이 Python 정수 기준과 일치 |
| 실패 시 출력 | TryInteger는 출력 보존, 내부 필드는 범위 예외 | 실패 출력 보존·예외 경로 대조 |
| 메모리 크기 | 곱셈 전 native 너비로 변환, 모든 곱·합 넘침 검사 | 실제 SDK 배열 함수의 할당·읽기·쓰기·해제·넘침 거부·복구 |
| 부호 있는 계산 | 효과 곱셈은 64비트 중간값, 빈 기록은 변환 뒤 1 감소 | 음수 효과, int 양끝, 곱 넘침, 빈 기록의 -1 유지 |
| 변경 명령 | 32비트 인덱스와 1바이트 명령 유지, 변경 전 범위 검사 | 실제 추출한 set/insert/erase/resize 5개 함수가 과대 입력에서 touch·자료·명령 보존 |
| 알림 식별자 | enum을 의도적으로 uint32 비트값으로 변환 | 원본 표 142개와 식별자 비트·순서 전부 일치 |
| Lua 입력 | native 변환 전 유한값·범위 검사, 이후 게임 필드 범위 검사 | 실제 Lua 보호 호출 74개 사례, 오류 39개와 이후 복구 39회 |
| FLua int | 기존 검증 실패 경로와 int 변환 특수화 | 실제 헤더에서 추출한 검증·변환 코드의 경계값 실행 |
| 재발 차단 | 기존 /W3에 C4244/C4267/C4838이 있으면 빌드 관문 실패 | attempt_009의 161개 오브젝트와 숫자 경고 0건 |

숫자 시험 프로그램은 /W4 /WX로 경고 없이 빌드되었고 단언 274,922회를
통과했사와요. 함수 추출 시험은 실제 수정 본문을 사용하되 소유자·할당 진입부는
독립 시험용으로 제공하므로 전체 GameCore 실행으로 계산하지 않사와요.
일반적인 메모리 고갈이나 모든 콜백의 원자적 복구를 증명한 결과도 아니랍니다.

Lua의 숫자 문자열, 비숫자 입력의 기본 0, optional 기본값은 기존 API 동작을
유지하와요. 실패는 Lua의 인수 오류 경로를 사용하며 Lua 정수 ABI 자체는
pointer 크기로 유지했사와요. 내부 C++ 범위 예외가 실행부 경계를 안전하게
통과하는지는 GameCore 통합 단계에서 추가로 검증해야 하와요.

## 실제 Lua 시험 제공자

SDK가 선언하는 Lua 5.1.4와 같은 공식 소스의 29개 C 파일을 x64 시험용
정적 라이브러리로 빌드했사와요. [공식 체크섬 목록](https://www.lua.org/ftp/)의
SHA-256 b038e225eaf2a5b57c9bcc35cd13aa8c6c8288ef493d52970c9545074098af3a와
일치하며 원본과 라이선스를 Source/ThirdParty/lua-5.1.4에 보존했답니다.

SDK의 lua.h·lauxlib.h·lualib.h는 줄바꿈 정규화 후 공식 소스와 같으며,
luaconf.h는 모듈 탐색 경로 두 군데가 다르답니다. 시험 제공자는 /MT이며
원본 소스의 64비트 shift 경고 3개를 기록했사와요. GameCore용 /MD 제공자와
전체 라이브러리 동등성은 아직 완료하지 않았사와요.

Lua 5.1 문서는 소수 입력의 정수 변환 반올림 방식을 고정하지 않사와요.
현재 시험은 같은 x64 제공자 안에서 변환 결과를 유지하는지 확인하였으며,
실제 SDK x86 라이브러리와의 소수 반올림 비교는 다음 관문이랍니다.
[Lua 5.1 정수 변환 계약](https://www.lua.org/manual/5.1/manual.html#lua_tointeger)

/we4244를 켜면 기존 /W3에 나오지 않던 int→short/char 등의 진단도 활성화되어
224곳이 더 드러났사와요. 지도 좌표·턴·외교 수치·로그 등의 별도 동작 검토
대상으로, 해결한 것처럼 계산하지 않사와요. stronger_warning_audit.json과
attempt_008에 보존했으며 명령 enum→1바이트 필드는 범위 검사로 추가 수정했답니다.

DLL 링크는 미해결 심볼 **342개**로 실패했사와요. 기존 339개에 새 입력 검사가
사용하는 luaL_argerror, luaL_checknumber, lua_tonumber 세 API가 추가된 결과랍니다.
현재 연결 조사에 x86 라이브러리나 성공을 가장하는 임시 구현은 넣지 않았사와요.

다음 작업은 실제 SDK x86 Lua와 공식 x64 소스의 동작 비교, 호환 수정,
GameCore와 같은 런타임의 제공자 빌드와 실제 연결 검증이와요. 이후 나머지
기반 서비스·x64 실행부, 게임 계산 병렬화·결정성·성능, 허가된 새 게임·턴·
저장/불러오기·UI·새 로그의 수용 관문을 완료해야 하와요.
