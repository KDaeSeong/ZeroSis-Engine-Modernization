# DB 캐시 실패 전달과 시작 단계 중단

2026-09-26 / 기존 572개를 보존하고 7개 패치를 추가했사와요. attempt_030의 실제 GameCore C++ 161개를 x64로 재컴파일하고 제공자 16개와 연결하여 미해결 0개·AMD64 DLL 생성을 확인했으며, 원본·수정본의 분리된 실행 프로그램으로 23,422개 검사를 통과했답니다. 이번 범위는 규칙 적재 오류를 상위에 전달하고 플레이어·팀 생성 전에 DB 단계의 실패를 멈추는 작업이와요.

| 요구사항 | 수용 기준 |
|---|---|
| DC01 | 62개 규칙 목록의 SQL 준비·순회·CacheResults 실패를 PrefetchGameData와 CacheGameDatabaseData에 전달 |
| DC02 | 잘못된 ID 형식·범위·중복을 거부하고, 미등록 항목을 정리하며 등록된 부분 목록은 호출자가 정리할 수 있도록 유지 |
| DC03 | Flavor 배열은 임시 소유 상태에서 완전히 읽은 뒤 교체; 실패하면 기존 배열과 개수 보존 |
| DC04 | 타입 조회 SQL의 준비·순회·null 문자열 오류를 전달하고, 기존 선택적 진단은 진단으로 유지 |
| DC05 | 필수 DB 단계 실패 뒤에는 플레이어·팀 생성 금지; 지역 로더 참조는 SDK Destroy 경계로 반납 |
| DC06 | 정상 입력의 목록·타입·Flavor 결과와 적재 순서를 기존 SDK 본문과 대조; 완료 전 캐시 성공 표시 금지 |

영향 파일은 CvDllDatabaseUtility.cpp/h, CvTypes.cpp, CvGlobals.cpp이랍니다. 기존 인터페이스 서명·객체 배치·저장 형식·모드 ID·스키마·밸런스는 유지하와요. 별도 프로젝트의 Source → Build → Stage로만 반영하며 설치 게임·SDK·MODS·저장 파일은 배포 대상이 아니랍니다.

실패 전에 등록한 전체 캐시와 전역 타입을 원자적으로 되돌리는 변경은 아니랍니다. 전체 GC 초기화 복구, 구체 정보 객체와 플레이어·팀의 생성 실패, 외부 참조 사용 종료, 실제 상태 소유 실행부는 후속 범위이와요. GameCore DLL 로딩·게임 실행·게임 멀티코어·성능 검증은 수행하지 않사와요.

## 검증 결과

| 검사 | 관측 결과 |
|---|---|
| 규칙 적재 순서 | 62개 목록 각각 CacheResults 실패를 주입; 수정본은 해당 목록에서 중단하고 다음 단계와 캐시 성공 표시를 실행하지 않음 |
| 재시도 | 호출자가 부분 상태를 정리한 뒤 같은 로더로 성공; 캐시 완료 후 재호출은 중복 적재하지 않음 |
| 직접 SQL 실패 | 없는 테이블·누락 ID 열·실제 SQLite 정수 오버플로 순회 오류를 거부 |
| ID 경계 | 유효한 음수 예약 행 제외·빈 ID 칸 보존; 범위 초과·소수·문자열·중복 ID 거부 |
| Flavor 배열 | SQL·스키마·범위·null·중복 등 8종 오류와 문자열 대입 예외에서 이전 배열·개수 보존; 재시도와 빈 테이블 MaxRows 규칙 확인 |
| 타입 조회 | 테이블 3개의 준비 오류와 순회 오류를 각각 전달; 기존 누락 열거값 진단은 비치명적으로 유지 |
| 시작 단계 | Defines 준비·후처리·캐시 실패 뒤 플레이어·팀 생성 차단; null DB·null 로더·실제 캐시 실패도 전파 |
| 로더 참조 | 정확한 SDK 인터페이스와 계측 참조 객체로 지역 참조의 Destroy 호출 확인 |
| 검사 수 | 원본 10,893개 + 수정본 12,529개 = 23,422개 |

GC 시험은 실제 init의 DB 조회부터 플레이어·팀 생성 호출까지 이어지는 본문을 추출한 것이랍니다. 앞서 만든 게임 소유 객체와 뒤의 경로 탐색기 생성은 실행하지 않사와요. 규칙 정보의 구체 클래스·게임 단계·문자열·호스트 객체는 시험 대체물이며, SQL은 검증된 실제 x64 데이터베이스 제공자에서 실행했답니다. 따라서 전체 규칙 효과·원본 게임 EXE·GC 전체 복구 증거와 구분하와요.

원본의 auto_ptr가 비가상 소멸자를 가진 SDK 인터페이스를 삭제하는 C5205 경고를 먼저 기록했사와요. 원본 비교에만 해당 경고 예외를 적용했으며, 수정본은 /W4 /WX에서 이 예외 없이 통과했답니다. SDK의 기존 TR1 사용에는 이름 공간 폐기 진단 설정을 사용했으며, 이를 TR1을 현대화한 결과로 표시하지 않사와요.

## 보유 DB 비교

프로젝트에 보관된 두 DB를 읽기 전용으로 열고 전후 해시를 확인했사와요. Civ5DebugDatabase.db에서는 목록별 ID·Type·빈 칸, Flavor 문자열, 전체 이름 조회표, 67개 지정 타입 값과 미션 개수가 원본과 수정본에서 일치했답니다. 구체 항목의 모든 CacheResults 효과를 비교한 것은 아니랍니다.

Civ5CoreDatabase.db에는 GreatWorkArtifactClasses와 GreatWorkSlots가 없었사와요. 원본은 누락을 지나 성공으로 처리했지만 수정본은 첫 필수 타입 조회에서 명시적 예외를 전달했답니다. 캐시 성공 표시는 남기지 않았고 액션 생성으로 진행하지 않았으며, 시험 호출자의 정리 후 잔존 객체는 0개였사와요. 이 입력은 BNW용 완전한 자료의 정상 동등성 비교로 집계하지 않사와요.

## 남은 범위

각 구체 CacheResults 내부에서 무시하는 하위 SQL 오류는 별도 조사 대상이랍니다. 전역 타입의 이전 세대 값 복원, 전체 캐시의 원자적 복구, SetGlobalActionInfo의 임시 버퍼·미등록 액션 소유권과 플레이어·팀의 직접 자식 생성 실패는 [후속 소유권 단계](M3_STARTUP_OWNERS.md)에서 보완했사와요. 중첩 자식 생성 실패와 전체 초기화 상태 관리는 남아 있답니다. 지금 확인한 것은 필수 단계 오류 전달과 지역 참조 반납이며, 이미 생성된 전체 게임 객체를 자동으로 복구하는 기능은 아니랍니다.
