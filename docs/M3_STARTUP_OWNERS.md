# 플레이어·팀·액션 생성의 직접 소유권

2026-09-26 / 기존 579개 패치를 보존하고 직접 소유권 패치 9개를 추가했사와요. attempt_031에서 GameCore C++ 161개를 x64로 재컴파일하고 제공자 16개와 연결하여 미해결 0개·AMD64 DLL 생성을 확인했답니다. SDK 수정 파일은 97개, 지원 헤더는 6개랍니다. 전체 GC 초기화 실패 복구에 필요한 하위 소유권을 보완하는 단계랍니다.

| 요구사항 | 수용 기준 |
|---|---|
| SO01 | 플레이어 하위 객체 26개를 생성 완료까지 임시 소유; 중간 할당·생성·reset 실패 시 이미 만든 직접 객체 정리 |
| SO02 | 정상 플레이어 종료에서 누락된 문화 객체 해제 |
| SO03 | 팀의 기술 객체를 생성 완료까지 임시 소유; 실패 후 재시도 가능 |
| SO04 | 이미 생성한 플레이어·팀 배열의 중복 초기화를 변경 없이 거부 |
| SO05 | 액션 정렬 버퍼와 아직 목록에 등록하지 않은 액션을 실패 시 정리; 크기 계산의 음수·넘침 거부 |
| SO06 | 정상 액션 순서·하위 유형·원래 인덱스·단축키 연결과 생성 성공 순서 보존 |

영향 파일은 CvPlayer.cpp, CvPlayerAI.cpp, CvTeam.cpp, CvDllDatabaseUtility.cpp이랍니다. 기존 클래스 필드·인터페이스·저장 형식·Mod ID·버전·스키마·밸런스는 유지하와요. 별도 프로젝트 Source → Build → Stage만 갱신하고 설치 SDK·게임·MODS·저장 파일은 유지한답니다.

전체 GC 시작 절차는 이후 호스트 준비 → 게임·지도·규칙 소유자 → DB → 플레이어 → 팀 → 경로 탐색기 단계로 관리해야 하와요. 종료 중 실패한 호스트 콜백의 재시도 계약, 외부 참조 사용 종료와 전역 타입 재설정까지 연결해야 전체 초기화 복구 관문을 통과할 수 있답니다. 이번 직접 객체 소유권 보완으로 그 관문을 완료 처리하지 않사와요.

## 변경 내용

플레이어의 26개 하위 객체와 팀의 기술 객체를 지역 unique_ptr가 보유하고, 기존 필드는 reset이 접근할 수 있도록 같은 객체를 가리키게 했사와요. 생성자 본문이 끝날 때 소유권을 기존 필드로 넘기며, 그 전에 예외가 발생하면 완료된 하위 객체들을 해제하와요. 새 게임에서 플레이어의 문화 객체를 만든 뒤 정상 종료에서 삭제하지 않던 누락도 보완했답니다.

플레이어·팀 정적 배열이 이미 존재하면 새 배열 할당 전에 logic_error를 전달하와요. 기존 배열 포인터와 플레이어·팀 ID는 보존한답니다. 이 검사는 한 실행 주체가 수명을 관리한다는 전제이며, 배열을 사용하는 모든 게임 작업의 동시 접근을 보호하는 잠금은 아니와요.

액션 생성은 기존 정렬 함수와 비교 함수를 그대로 사용하와요. 버퍼의 4배 인덱스 연산 전에 음수·signed int 범위를 검사하고, 버퍼와 미등록 액션의 소유권을 지역 객체로 유지하와요. 목록 등록이 끝난 액션은 기존 목록이 계속 소유하므로 실패 후 호출자가 정리할 수 있답니다. 이미 변경한 규칙의 액션 인덱스와 단축키 값을 되돌리는 트랜잭션은 아니와요.

시험은 실제 SDK 생성자 본문·소멸자·정적 배열 생성/삭제·액션 생성·정렬 본문을 추출하와요. 플레이어의 긴 멤버 초기화 목록은 실행하지 않으며, 실제 수정에서 해당 목록을 바이트 그대로 유지했는지 별도로 대조하와요. 하위 객체의 실제 구현, 플레이어·팀 reset, 비활성 멤버 저장소, 단축키 서비스는 계측용 대체물이랍니다. 특히 파생 생성자 실패 때에는 C++가 완성된 기반 클래스 소멸자를 실행하므로 원본에서도 이미 일부 자식이 정리되는 현상을 구분해 검증했사와요.

따라서 326개 실패 사례가 모든 중첩 하위 생성자·게임 효과·전체 GC 복구를 증명하는 것은 아니랍니다. 단축키·메타데이터 경계의 일부 예외는 합성 주입이며 실제 해당 단순 setter가 예외를 던진다는 주장도 아니와요. 실제 프로그램의 모든 소유권과 게임 실행을 대신하는 증거로 사용하지 않사와요.

## 남은 초기화 관문

이 단계 당시 남아 있던 시작·준비·정리 상태와 중복·재진입 거부·단계별 정리 기록은 [후속 GC 수명 제어](M3_GC_LIFECYCLE.md)에 연결했사와요. 호스트의 부분 InitGlobals 뒤 UninitGlobals가 처리할 범위와 실패 재시도 조건도 새 실행부 계약에 연결해야 하와요. 전역 타입의 이전 세대 값, 구체 정보 객체 내부의 실패, 경로 탐색기 생성 실패와 외부 참조 사용 종료까지 점검해야 한답니다.

이번 단계에서 다룬 것은 직접 소유 포인터랍니다. 하위 생성자 자신이 실패하며 남기는 내부 raw 포인터, 기존 게임 진행 중 reset(false)의 복구, 액션 메타데이터의 일괄 복원은 별도 범위이와요. GameCore DLL 로딩·실게임·저장 호환·게임 멀티코어 성능은 검증하지 않았사와요.
