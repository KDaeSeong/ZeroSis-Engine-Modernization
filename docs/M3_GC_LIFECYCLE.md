# 전체 GameCore 초기화·종료 제어

2026-09-26 / attempt_032에서 기존 588개와 새 12개, 합계 600개 패치로 실제 GameCore 161개를 재컴파일했사와요. SDK 수정 파일 98개·지원 헤더 7개랍니다. 독립 실행은 1,747개 검사를 통과했으며 제공자 16개와 정식 AMD64 DLL 연결·미해결 심볼 0개도 확인했사와요.

목표는 실제 CvDllGameContext의 Init/Uninit을 통해 GC의 시작·준비·정리·정리 대기 상태를 관리하는 것이랍니다. 기존 실행부 연결 변경과 같은 잠금으로 중복·동시·재진입 변경을 거부하고, 초기화 예외가 나면 완료된 자원까지 정리하와요. 정리 중 예외가 나면 끝난 단계를 반복하지 않고 실패한 단계부터 재시도하며, 그동안 새 초기화·실행부 교체·컨텍스트와 힙 종료를 거부하와요.

영향 범위는 별도 x64 이식본의 CvGlobals.cpp/h, CvDllContext.cpp, CvTypes.cpp/h와 내부 지원 헤더랍니다. 클래스 필드·가상 인터페이스·저장 형식·Mod ID·버전·밸런스는 유지하와요. 설치 SDK·게임·MODS·저장 파일은 변경하지 않으며 Source → Build → Stage로 검토본을 추적하와요.

| 요구사항 | 수용 기준 |
|---|---|
| GCL01 | 실제 문맥 진입점에서 중복 시작과 동시·재진입 변경 거부 |
| GCL02 | 실제 GC 초기화 본문의 모든 직접 할당과 호출 경계 실패에서 정리·원래 예외 전달·재시도 검증 |
| GCL03 | 기존 정리 순서를 보존하고 45개 단계의 완료 위치를 기록; 호스트 정리 실패 후 완료 단계를 반복하지 않음 |
| GCL04 | Ready·CleanupPending 상태에서 실행부 교체와 컨텍스트/힙 종료를 변경 없이 거부 |
| GCL05 | 초기화에 들어간 호스트만 정리; 부분 InitGlobals 실패도 정리 대상에 포함 |

| GCL07 | 원본 소스의 정상 초기화·정리 호출 순서와 비교하고 실제 161개 SDK 소스를 재컴파일·연결 |

호스트는 부분 InitGlobals 이후에도 UninitGlobals를 호출할 수 있어야 하며, 정리 콜백이 일부 작업 뒤 예외를 던졌다면 재호출해도 중복 해제가 없어야 하와요. 이 계약은 새 실행부가 구현해야 하며 기존 비공개 실행부의 동작을 보장하지 않사와요. 일반 게임 호출과 외부 참조는 수명 변경 전에 호스트가 정지해야 한답니다.

독립 실행에서는 실제 GC·문맥 함수 본문과 실제 상태 제어 헤더를 사용하되, 게임·지도·규칙·플레이어·팀·경로 탐색기와 호스트/DB 서비스는 계측용 대체물을 사용하와요. 모든 중첩 생성자·소멸자와 실제 게임 상태의 실패 복구를 증명하는 시험은 아니랍니다. noexcept 소멸자의 종료, 접근 위반, 강제 프로세스 종료는 일반 C++ 예외 복구 범위에 포함하지 않사와요.

실제 GameCore DLL 로딩, 새 게임·턴 진행·저장 호환·게임 멀티코어 성능과 외부 차용 객체의 종료는 후속 실행부 관문이랍니다.

현재 GC 소스의 38개 직접 포인터 정리, 플레이어·팀 정리, DB 질의·로더 반납, 호스트 정리, 정보 목록 정리와 타입 재설정을 기존 순서의 45개 단계로 구성했사와요. 기존 세부 부품 검사는 대체 부분 상태를 실제 제어기에 등록한 뒤 현재 GC 정리 본문을 실행하도록 갱신했답니다. 해당 검사에서 실제 전체 초기화를 수행했다는 뜻은 아니와요.

초기화가 예외를 던지고 자동 정리도 실패하면 최초 초기화 예외를 유지하며 상태는 CleanupPending에 남아 있사와요. 호스트는 Init 실패 뒤 Uninit을 호출해 정리를 완료한 다음 다시 Init하거나 종료해야 하와요. 아직 일반 게임 호출의 진입·외부 인터페이스 차용을 모두 추적하는 제어부는 아니랍니다.
