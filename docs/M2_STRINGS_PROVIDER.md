# 문자열 제공자 x64 이식

2026-09-24: 실제 GameCore 연결에서 FString·UTF 변환·문자열 스트림 **12개 항목을 해결하여 전체 미해결 항목을 64→52개**로 줄였사와요. 새 미해결 항목은 없으며 GameCore DLL과 전체 실행부는 아직 미완료랍니다.

영향 범위는 독립 프로젝트의 `Source/Providers/Strings`, 시험 코드, 빌드·검증 도구와 검토용 Stage랍니다. 원본 SDK·게임·설치 모드와 저장 파일은 변경하지 않사와요. SDK 객체 배치와 기존 문자열 저장 형식은 보존하며, 경계 오류의 수정은 원본 관측과 후보 검증을 구분하여 기록하겠사와요.

완료 조건은 실제 원본 x86 라이브러리와 x64 구현의 정상 동작 비교, 고정 버퍼·중첩 입력·크기·할당 실패·잘린 입력 처리 검증, 그리고 해당 구현으로 실제 GameCore 링크 요구사항을 해소하는 것이랍니다. 이번에 이 범위를 검증했으며 전체 게임 실행·저장 호환성·멀티코어 성능 검증은 남아 있답니다.

## 구현과 유지한 계약

- `SdkStrings.cpp`는 좁은/넓은 문자열의 복사·추가·대체·용량·버퍼 수명, 원본 형태의 빈 문자열, 좁은 문자열 서식, 경로 제목과 UTF 변환을 구현하와요. `SdkStringStream.cpp`는 FStringA 필드 읽기·쓰기를 제공하와요.
- 객체는 포인터 하나이고 자료 헤더는 12바이트랍니다. 길이·용량은 기존 int32 범위를 유지하고 넘치는 요청을 거부하와요. 저장 길이는 4바이트이고 본문은 종료 문자를 제외한 원시 바이트랍니다.
- 기존 인라인 소멸자가 사용하는 `delete[] byte`와 일치하는 할당을 사용하와요. 교체 메모리와 중첩 입력의 복사본을 준비한 뒤 기존 문자열을 수정하며 고정 버퍼를 해제하지 않사와요.
- 좁은 문자열은 32문자, 넓은 문자열은 16문자 단위의 원본 용량 증가를 보존하와요. 직접 자기 버퍼를 지정한 `Copy`의 원본 무동작도 보존하와요.
- `ExtractFileTitle`은 원본이 실제로 반환하는 **확장자를 포함한 파일 이름**을 유지하와요. 지정한 경로 구분자의 마지막 위치, 구분자가 없으면 첫 콜론 뒤를 사용하며, 검색은 첫 NUL까지 진행하와요.
- UTF 변환은 원본과 같은 Windows CP_UTF8·flags=0·NUL 종료 입력이랍니다. 한글·보충 문자·잘못된 UTF·BOM을 비교했으며, 내장 NUL 뒤의 글자는 변환하지 않는 원본 동작을 보존하와요.
- Format은 문자열·정수·문자·명시적 64비트 정수와 원본의 포인터 하나짜리 클래스 인수 전달을 시험했사와요. 내장 NUL에서 길이가 끝나는 원본 동작도 유지하와요. 클래스 가변 인수 전달은 MSVC 전용이며 해당 시험 한 줄의 C4840만 명시적으로 억제하와요.
- 쓰기 버퍼를 요구하는 빈 문자열에는 개별 메모리를 할당하므로 공유 빈 값이 수정되지 않사와요. 길이 탐색은 실제 버퍼 용량으로 제한하와요.

## 원본에서 재현하고 수정한 결함

| ID | 원본 재현 | 새 구현과 검증 |
|---|---|---|
| STR01 / P1 | `abcdef` 내부의 두 번째 위치부터 3글자를 복사하면 `bc\0`이 됨 | 입력을 먼저 보존하여 `bcd` 반환, 좁은/넓은 문자열 모두 확인 |
| STR02 / P1 | `abcdef`에 `Reserve(2)`를 호출하면 길이는 6이지만 내용이 `ab\0def`로 손상됨 | 작은 예약은 기존 내용을 유지, 두 문자 폭 모두 확인 |
| STR03 / P1 | 고정 버퍼 16칸에 16글자를 넣으면 종료 문자가 다음 멤버의 경계 표식을 덮어씀 | 종료 문자 공간을 포함해 판단하고 별도 메모리로 확장, 두 문자 폭의 표식 0x7b 유지 |

원본 결함 관측은 별도 모드로 기록하여 정상 동작 일치율에 섞지 않았사와요. 세 수정은 기존 텍스트와 메모리 경계의 손상을 방지하며, 실제 지도 이름·로그·저장 소비자의 회귀는 후속 게임 통합 관문이랍니다.

## 실행 증거

| 검증 | 결과 |
|---|---|
| 실제 원본 코드 | VC9 x86, SDK FireWorksWin32·CvGameCoreDLLUtilWin32 아카이브와 링크 지도 확인 |
| 후보 | VS2022 x64, 동일한 제품 오브젝트 2개와 시험된 Streams 제공자, /MD·/W4·/WX, 출력 경고 0개 |
| 독립 실행 의존성 | 세 시험 실행 파일의 CRT·Windows 의존성 검사, GameCore 로드 없음 |
| 정상 실행 기록 | 값·고정 버퍼와 서식·경로·UTF·스트림·혼합 조작의 6종이 두 아키텍처에서 정확히 일치 |
| 혼합 조작 | 아키텍처별 8,192회, C++ 표준 문자열 모델과 별도 Python 모델 일치 |
| 저장 필드 | 3개 바이트 순서, 411필드·433,098바이트가 원본·후보·Python 구조 기준에 정확히 일치 |
| 교차 읽기 | 각 작성자의 파일을 x86·x64가 모두 읽는 네 번의 실행 통과, 작성자별 두 기록 일치 |
| 경계·오류 | 잘못된 크기·범위·잠금 16건 거부, 잘린 읽기·실패 쓰기·과대 길이 15건 거부 |
| 할당 실패 | 제품 오브젝트 그대로 15개 연산의 20개 할당 실패 주입, 기존 값·포인터·할당 수 보존, 15개 정상 경로 확인 |
| 추가 경계 | 중첩 자기 추가·자기 서식·빈 값 버퍼 소유·종료 문자 누락의 제한 탐색·16,384바이트 서식 처리 |
| 전체 독립 시험 | 21회 실행·45,068회 단언, 이 중 실패/경계 시험 4,428회 |
| 실제 GameCore 연결 | 12개 요구 항목 모두 구현으로 해소, 추가 미해결 0개, 전체 미해결 52개 |

원본 시험의 C4819는 기존 SDK 헤더의 코드 페이지 경고랍니다. 후보 컴파일과 시험 코드에는 출력 경고가 없으며 SDK 외부 헤더는 기존 제공자와 같은 별도 경고 수준을 사용하와요. GameCore 자체의 기존 경고 343개는 이번 변경으로 없어졌다고 계산하지 않사와요.

## 재현·배포·남은 관문

프로젝트 폴더에서 `build_string_provider.py --vs <VS 경로>`, `verify_string_provider.py`, 기존 전체 연결 명령에 `--string-provider evidence/strings/build_result.json` 추가, `stage_sdk_x64_port.py`, `verify_project.py` 순서로 재현하와요. 원본 비교의 빈 값 export는 독립 시험 호스트가 제공하며 실제 문자열 함수 본문은 원본 아카이브를 사용하와요. 제품은 별도 x64 빈 값 저장소를 사용한답니다.

Stage의 `GameCore_x64/Providers/Strings`에는 소스·시험·도구·정적 라이브러리·검증 기록과 교차 읽기 자료를 보관하와요. 원본 SDK 헤더나 GameCore 객체 배치를 수정하지 않았으므로 attempt_015의 161개 오브젝트를 그대로 연결했사와요.

FString 전체 공개 API, 모든 서식 지정자와 로캘·부동소수점 출력, 실제 실행부의 문자열 소유권·종료 순서, 같은 문자열 객체의 동시 수정은 아직 별도 작업이랍니다. 원시 포인터 입력의 외부 메모리 크기는 호출자 계약이며 일반적인 유효성 탐지 기능이 아니와요. 읽기 실패 시 목적 문자열은 보존하지만 이미 읽은 스트림 위치와 여러 필드 전체를 되돌리지는 않사와요. 전체 저장·모드·한글 UI·멀티플레이·멀티코어 성능은 실게임 관문으로 남아 있답니다.
