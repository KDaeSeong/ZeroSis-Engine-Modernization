# 지도 파일 형식의 x64 읽기·쓰기와 명시적 복구

2026-09-25 / `WORLD_BUILDER_MAP_WIRE_COMPONENT_PASS`. 실제 SDK 지도 객체에 연결하기 전의 파일 구성요소 단계랍니다. GameCore의 미해결 연결 항목은 여전히 **17개**이며 DLL·실행부·실게임 검증은 남아 있사와요.

## 요구사항과 영향 범위

| 요구사항 | 구현과 검증 |
|---|---|
| WB05-F1 | 설치 파일에서 관측한 버전 6·7·9·10·11·12의 이름·형식 표·지도·시나리오 구획을 고정 폭으로 읽고 쓰기 |
| WB05-F2 | 파일 길이·필드 개수·지도 크기·참조·연결 목록을 검증한 뒤 소유 문서 반환; 실패 때 입력 보존 |
| WB05-F3 | 원본 x86 SDK 읽기 함수와 공개 지도 값 대조, 실제 파일 왕복과 변경한 문서의 원본 재읽기 |
| WB05-F4 | 손상된 빈 슬롯 목록은 기본 경로에서 거부; 별도 복구 선택과 변경 기록·원본 보존 |
| WB05-F5 | Source → Build → 별도 Stage, 원본 SDK·지도·설치 게임·MODS·저장 무변경 |

제품 파일은 `WorldBuilderMapWire.h/.cpp`이며 기존 `SdkWorldBuilderModDataWire`의 길이 검사도 사용하와요. `MapDocument`는 이름 붙은 31개 구획과 메타데이터를 소유하며, 네이티브 클래스의 메모리 배치를 파일에 복사하지 않사와요. SDK의 Mod ID·버전·저장 키·스키마·효과·밸런스는 변경하지 않았답니다.

## 원본에서 확인한 형식

원본 VC9 정적 라이브러리의 실제 `CvWorldBuilderMap::Save/Load`를 격리 실행했사와요. 시험용 파일 어댑터는 메모리 바이트를 전달할 뿐이며 지도 함수 본문을 대신하지 않사와요. 원본과 후보 모두 가져오는 DLL을 확인한 뒤 실행했고 GameCore를 로드하지 않았답니다.

- 첫 바이트 하위 7비트는 버전, 상위 비트는 시나리오 포함 표시이와요. 지원 버전의 플레이 가능 문명 수 바이트는 시나리오 유무와 관계없이 존재하와요.
- 지도 크기·길이는 little-endian 32비트이며 지도·시나리오 타일은 각각 8바이트이와요. 파일용 유닛·도시·플레이어 기록 폭은 버전별로 다르므로 x64 `sizeof`로 계산하지 않사와요.
- 버전 6은 지도 이름이 없고, 11부터 세계 크기 문자열이 추가되며, 10부터 도시 국가 영향력 구획이 있사와요. 9 이상에서 판독한 유닛 승급·사용자 이름 구획도 버전별로 처리하와요.
- 팀 관계 5종, 플레이어별 도시 국가 영향력 64칸, 팀별 타일 가시성, 팀·플레이어·도시 국가 배열과 타일별 도시·유닛 참조를 분리하와요.
- 버전 0–5·8과 13 이상은 이번 구현에서 명시적으로 거부하며 추가 원본 조사 대상으로 남겨 두었사와요.

전체 파일은 32비트 파일 길이 계약과 SDK의 최대 32,768타일 범위를 따르와요. 잘린 입력·뒤에 덧붙인 자료·문자열 종료 누락·구획 크기 불일치·잘못된 참가자 수·부가 데이터와 타일 수 불일치·범위를 벗어난 핸들·순환 유닛 목록·복수 타일의 동일 도시/유닛 소유를 거부하와요.

## 실제 지도와 복구 결과

설치 지도 **128개**와 원본이 생성한 시험 파일 **2개**, 합계 **130개·15,712,559바이트**를 처리했사와요. 모든 파일의 31개 구획과 헤더를 별도 Python 판독 결과와 대조하고, 출력 파일을 원본 SDK 읽기 함수로 다시 읽었답니다. 설치 파일은 처리 전후 해시가 같사와요.

설치 지도 **125개**와 시험 파일 **2개**는 모든 바이트가 그대로 왕복했사와요. 아래 3개는 원본 읽기 함수가 받아들이지만 빈 슬롯 목록의 다음 참조가 범위를 벗어나므로, 기본 후보 읽기는 거부하와요.

| 원본 파일 | 손상된 풀 | 복구 사본에서 달라진 바이트 | 원본 SDK 공개 상태 기록 비교 |
|---|---|---:|---:|
| MongolScenario.Civ5Map | 도시 | 7 | 589,954바이트 정확히 일치 |
| 1066Scenario.Civ5Map | 유닛 이름 | 4 | 630,598바이트 정확히 일치 |
| CivilWarEasternTheater.Civ5Map | 유닛 | 32 | 300,499바이트 정확히 일치 |

`MapReadPolicy::RebuildInvalidFreeLists`를 명시한 경우에만 복구하와요. 먼저 타일에서 연결되는 도시·유닛·이름을 범위와 중복·순환 검사로 확정하고, **손상된 풀에서 참조되지 않는 슬롯**으로 빈 목록을 다시 구성하와요. 변경은 해당 풀의 4바이트 머리 값과 미참조 슬롯의 다음 값으로 제한하며, 정상 풀의 미참조 할당 객체는 보존하와요. 이 정책은 손상된 풀에서 잃어버린 원래 할당 여부를 추정해 되살리는 기능이 아니며, 참조되지 않는 슬롯을 재사용 가능하게 분류한다는 계약이랍니다.

독립 모델이 변경 가능한 바이트와 복구 결과를 정확히 대조하고, 원본 SDK로 원본·복구 사본을 읽어 실제 참조 객체의 상태 기록 **1,521,051바이트**가 동일함을 확인했사와요. 기록에는 타일·도시·유닛·이름·플레이어·팀·승급/건물/정책·관계·가시성·영향력·부가 데이터·게임 옵션을 포함하와요. 원본 판독기는 입력의 형식 표를 사용하며, 영향력 구획이 없는 구형 파일은 시험의 사전 상태를 0으로 명시해 미초기화 메모리를 비교 기준으로 삼지 않았답니다.

복구 여부는 `recoveredAllocators`로 반환하며 파일에는 새 필드나 새 버전을 추가하지 않사와요. 호출자는 복구 기록을 남기고 별도 파일로 저장해야 하며 원본을 조용히 덮어쓰지 않아야 하와요. 이 경로는 아직 실제 게임 로더에 적용되지 않았답니다.

## 독립 실행 검증

- 후보 경계·실패 검사 **13,639회** 통과, 시험 시나리오의 모든 짧은 길이 **6,530가지** 거부.
- 읽기·쓰기·복구 작업에서 할당 실패 **146건**, 각 작업의 성공 경로 **3건** 확인; 예외 뒤 살아 있는 할당 수와 입력 문서 보존.
- 독립 작업자 4개에서 문서 읽기·쓰기 **128회** 확인. 공유 GameCore 상태의 병렬 계산 증거로 계산하지 않사와요.
- 지도 이름 길이·플래그·최대 턴·자원량을 바꾼 출력 파일을 원본 SDK가 정확히 읽는 것을 확인했사와요.
- 직접 작성한 x64 제품 오브젝트 2개와 소비 프로그램은 `/MD /W4 /WX`로 경고 없이 빌드했사와요. 연결 지도에서 실제 `WorldBuilderMapWire.obj` 함수가 사용되었음을 확인했답니다.

## 남은 통합 관문

`CvWorldBuilderMap` 생성·초기화·크기 변경·플레이어 교환·SDK 타입 변환과 실제 `FIFileSystem` 연결은 아직 구현·통합 대상이랍니다. 특히 버전별 파일 기록을 현대 C++ 객체로 옮길 때 비트 집합·기록 폭·핸들·소유권과 실패 후 전체 상태 보존을 검증해야 하와요. 이번 파일 구성요소의 통과를 지도 객체 13개 연결 항목의 해소로 계산하지 않사와요.

전역 열거형 호출부 결함 후보, 모든 지도 버전·임의 사용자 지도·전체 게임 저장·모드 조합·실게임 턴·멀티코어 성능도 남아 있답니다.
