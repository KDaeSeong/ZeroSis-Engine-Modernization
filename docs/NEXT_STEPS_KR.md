# ZeroSis 문명 5 엔진 후속 개발 계획서

2026년 11월 21일 · Windows x64 · 기준 커밋 [86ef92a](https://github.com/KDaeSeong/ZeroSis-Engine-Modernization/commit/86ef92affe67b82e02c0789e25961b9de6eda465)

목표는 문명 5의 원래 UI·조작·3D 세계·게임 규칙을 유지하면서 실행부(Host)와 확장팩 Brave New World(BNW)의 게임 규칙 모듈(GameCore)을 64비트로 구동하고, 독립 계산을 여러 코어로 분산하는 것이다. 첫 목표는 새 작업 환경에서 12단계 전체 Host와 SDK를 한 격리 묶음으로 식별하고 재검사하는 것이다. 현재는 V2 월드 지형 그리기와, 화면 없이 실행하는 x64 Host의 실제 턴 측정을 각각 검증했다.

## 첫 주 작업과 빌드 재현

개발자 한 명을 기준으로 잡은 **5작업일 제안**이다. 입력 인수에 드는 시간은 별도다. 과거 빌드 계획이나 검증 결과를 회수할 수 없으면 해당 ID의 재현을 보류하고 새 입력 명세와 후보 ID로 검증을 시작한다. 그동안 소스 검사와 곡면 통합 검토를 먼저 진행할 수 있다.

| 시점과 담당 | 실행할 작업 | 완료 기준과 산출물 |
| --- | --- | --- |
| 1일차 · 빌드 | BNW SDK 원본·수정 대상, 게임 자산, `ThirdParty`, `UiPopupAssets.generated.h`, 빌드 계획·이전 결과 파일의 경로와 제공처를 대조한다. | 입력마다 경로·기대 해시·실제 해시·누락 사유가 있는 목록 1개. 과거 스크립트의 절대경로도 표시한다. |
| 2일차 · SDK | 새 `Source/SDK_BNW_x64`에 검증된 원본의 복사본을 놓고 패치를 적용한다. `Source/SDK_BNW_Original`을 비교 기준으로 보존한다. | manifest의 원본·수정 후 각 1,105개 파일 대조. 변경 경로 117개, 패치 역방향 검사, 저장소 검사 통과. |
| 3일차 · 빌드 | 12단계 계획의 컴파일러·라이브러리·동결 입력을 복원한다. 보존한 Host가 있으면 기록 해시를 확인하고, 빌드할 때는 도구와 실제 입력을 함께 기록한다. | 후보 EXE의 AMD64 형식, 링크 결과·경고·SHA를 확인한다. 도구나 입력이 달라진 빌드에는 새 후보 ID를 준다. |
| 4~5일차 · 통합 | 후보 Host와 SDK430을 새 게임 전용 격리 묶음에 연결한다. 11단계의 자산·UI 공유, 개별 DB, 사전 검사 규칙을 재사용한다. | Host·SDK·6팩의 해시, 잘못된 경로·해시와 다른 묶음 저장의 거부, 기존 저장·기본 실행 경로 보존을 확인한 파일 검증표 1개. |

**SDK 복원의 검사 순서.** 저장소 루트에서 원본 파일별 SHA를 먼저 맞춘다. 깨끗한 수정용 복사본에 `git apply --check patches/sdk-bnw-x64.patch`가 통과하면 `git apply patches/sdk-bnw-x64.patch`를 적용한다. 이어서 `git apply --reverse --check patches/sdk-bnw-x64.patch`와 `python -B tools/refresh_sdk_version_control.py --check`로 수정 트리와 인덱스를 검증한다. 두 SDK 폴더가 없는 복제본에서는 마지막 명령이 소스 인덱스만 검사한다.

## 지형과 물 렌더링의 구현 순서

12단계에는 높이장의 u16 확정, 원본 높이 단위 반영, 물 반사를 그릴 때와 샘플링할 때 같은 투영 행렬을 쓰는 변경이 들어 있다. 이어질 작업은 **원본에서 확인한 입력을 실제 렌더러까지 연결하는 것**이다. 곡면·카메라·숲의 인계 부품은 공통 렌더러를 바꾸기 전에 개별 검토한다.

| 우선순위와 선행 조건 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| P1 · 곡면 기저와 월드 배치 / 구현 완료 | Mitchell–Netravali 기저(B=¾, C=0), 원본 셀 원점과 축별 간격, 투영 크기에 따른 다섯 격자 단계를 V2 월드에 연결했다. | 소프트웨어 D3D11에서 줌 전환, 경계 좌표와 높이, 타일 선택 및 그림자 그리기를 검증했다. 원본의 높이 밉과 근접 분할, 실제 카메라 화면 대조가 다음 작업이다. [지형 구현 기록](WORLD_TERRAIN_ORIGINAL_PLAN.md#줌에-따른-지형-세부-단계와-셀-접합) |
| P1 · 지형 캐시 / 원본 입력 | 공유 scratch의 128·256·512 해상도에서 필터·밉·압축 캐시를 거쳐 최종 재질을 샘플링하는 경로를 잇는다. 현재 청크의 68/66 경계와 좌표를 대조한다. | 같은 경계 표본에서 높이와 재질 좌표를 독립 계산과 비교한다. 감싸기·미탐색 경계와 정수 타일 선택 ID를 보존한다. |
| P1 · 카메라와 물 / 좌표 근거 | 실제 세계 카메라의 인스턴스·시야각·줌·클립과 단위를 확정한다. 반사용 8점 범위와 축, 수면 클립면은 물 전용 입력으로 연결한다. | 투영·반사 UV·잘림에 고정 표본을 둔다. 지형의 정적 t9와 물의 동적 Raw를 구별하고, 입력이 없으면 원본 반사 경로를 비활성으로 둔다. |
| P2 · 숲과 반사 장면 / 원본 모델 | 숲 GR2 해독·배치 규칙을 기존 숲 부품에 연결한다. 얼음의 균열·픽셀 셰이더·그리기와 불가사의·랜드마크 반사 공급자를 각각 보완한다. | 공급자별로 원본 자산, 좌표와 가시성 검사를 연결한다. 원본 배치·외형 수락은 같은 시드·카메라의 화면 대조에서 판정한다. |

인계 시점에 곡면 기저는 정적 근거와 CPU 부품이 확보됐고, 세계 카메라는 후보 단서까지, 숲 GR2 해독·배치는 미착수였다. 캐시와 반사 계산은 별도로 검토할 수 있다. 두 경로를 합친 다음에는 물가·청크 경계·미탐색 지형에서 화면의 타일과 실제 선택되는 타일이 일치하는지 확인한다.

## 플레이와 저장 호환성 검증

실게임·화면 검증은 프로젝트에서 보류 중이다. **사용자가 재개하고 격리 묶음의 파일 검증이 끝나면** 아래 순서로 진행한다. 첫 플레이는 새 게임 전용 후보로 시작한다. 저장 재개 시험은 같은 묶음의 개발 저장 복원을 지원하는 후보에서 진행한다.

| 순서와 담당 | 시험할 경로 | 남길 판정 근거 |
| --- | --- | --- |
| 1 · 실행부 | x64 Host에서 BNW GameCore를 로드하고 새 게임을 연다. 통제 시험에서 32비트 주소 범위 밖에 배치한 게임 데이터의 읽기·쓰기·해제를 확인한다. | 게임 상태를 소유하는 프로세스와 로드 모듈 목록, 실제 주소와 수명 기록. F01·F02 |
| 2 · UI와 게임플레이 | 사람이 새 게임→도시 건설→연구·생산 선택→유닛 행동→턴 종료를 진행한다. 전투·점령·외교와 승리 또는 패배까지 장기 시나리오로 확장한다. | EN·KO 1920×1080에서 원본 HUD·메뉴·지도·모델·효과, 입력 대상·팝업 복귀·잘림을 같은 장면에서 대조한다. 규칙 차이와 화면 차이를 기록한다. F05·N04 |
| 3 · 개발 저장 | 격리 세션에서 `.zssave`를 쓰고 종료한 뒤, 같은 후보의 새 프로세스로 불러와 한 턴 더 진행하고 재저장한다. | 턴·도시·유닛·생산·연구·난수 상태를 비교한다. 허용된 세션 메타데이터 차이를 명시하고 기존 사용자 저장의 해시를 확인한다. |
| 4 · 원본 저장과 모드 | BNW `.Civ5Save` 대표 사본으로 읽기·상태 복원·새 경로 쓰기를 각각 검증한다. 모드 없는 기준판과 대표 ZEROSIS 조합을 따로 시험한다. | 저장 지원표에는 읽기와 쓰기 결과를 분리한다. 모드 표에는 ID·버전·로드 순서·DLL 의존성·SQL/XML·Lua 이벤트·UI 콜백의 지원 범위를 남긴다. F06·F07 |

**실패 판정.** 원본 저장을 실제 상태로 복원하기 전까지 해당 형식의 읽기 지원은 미검증으로 둔다. 지원 밖 저장이나 모드 조합은 활성 세션을 바꾸기 전에 거부해야 한다. 진행이 막히면 같은 시드·마지막 입력·저장 사본으로 재현하고, 독립 시험과 실제 플레이의 결과를 개별 기록한다.

## 성능과 릴리스 판단

**멀티코어 수락 기준은 같은 결과와 반복 측정 가능한 턴 시간 단축이다.** 먼저 BNW 버전·모드·지도·시드·명령열과 측정 장비를 고정한다. 같은 언어의 직렬 실행을 기준으로 워커 1·2·4개를 비교하고, 표시는 프레임 시간, 시뮬레이션은 전체 턴 시간으로 나누어 기록한다.

그리스·로마 초반에는 실제 Host와 BNW GameCore로 2→3턴, 3→4턴을 모드별 네 번씩 측정했다. 직렬의 두 턴 합계 중앙값은 48.514ms였다. 도시 입지 평가 워커를 1·2·4개로 바꾸면 각각 53.806ms, 61.348ms, 54.645ms였다. 모든 모드에서 상태와 난수, 명령 순서가 일치했다. 지도 GUID 16바이트를 정규화한 뒤 최종 저장 133개 구획도 일치했다. 측정한 지도에는 도시가 없었으므로 중후반 성능은 아래 시험의 대상으로 남는다. [실측 조건과 원자료](M5_FULL_TURN_BENCHMARK.md)
