# 실행부 연결 교체와 종료 소유권

## 실제 해제 계약과 검증 범위

SDK 주석은 QueryInterface로 새 소유 인스턴스를 얻는다고 명시하와요. 이 연결 계약에서 같은 포인터는 동일 소유 객체로 취급하며 추가 참조를 얻었다고 해석하지 않사와요. 일반적인 COM 참조 계수 계약을 구현한 것이 아니므로, 새 실행부도 이 소유권 계약을 따라야 한답니다. 입력 인터페이스는 호출 동안 차용하며, 성공한 조회 결과만 GameCore가 소유하와요. Destroy는 예외를 던지지 않아야 한답니다.

시험은 SDK의 SetDLLIFace, ShutdownSingleton, bootstrap DestroyContext와 ICvUnknown 정의·GUID를 추출하여 사용하와요. 실행부의 나머지 서비스 슬롯과 컨텍스트 내부 객체는 관측 가능한 대역이며, 완전한 실행부 ABI나 실제 GameCore 생성 시험은 아니랍니다.

원본의 비가상 기반 객체 삭제에는 컴파일러 C5205 진단이 발생했으며 최초 로그를 보존했사와요. 원본 재현용 추출 본문에만 해당 진단을 국소 허용했으며, 관측 결과는 해당 MSVC 빌드의 동작이랍니다. 원본의 자기 별칭·동시 변경 경로는 실행하지 않았고, 남은 포인터를 역참조하지 않았사와요. 수정본은 이 예외 없이 /W4 /WX로 빌드했답니다.

## 남은 실행부 관문

이 게이트는 연결 변경만 보호하와요. 게임 호출·차용 인터페이스 전체를 추적하거나 자동 중지하지 않으므로, 교체·종료 전에 모든 차용 객체와 게임 호출을 정지하는 것은 실행부의 필수 계약이랍니다. GC.init/uninit 전체의 실패 복구·중복 방지·상태 전이, DB 오류 전달, 나머지 생성자 실패 처리와 실제 x64 실행부가 남아 있사와요.

게임 상태를 초기화한 실행부는 게임 작업 종료와 `Uninit()`을 먼저 완료하고, 받은 SDK 객체를 반납한 뒤 `ZeroSisShutdownGameCore()`를 호출해야 하와요. 성공한 종료 뒤에만 모듈을 해제하는 순서랍니다. 이번 ShutdownSingleton 수정은 GC.uninit을 자동 실행하거나 이 전체 상태 순서를 강제하지 않으므로, 새 실행부의 상태 관리가 이 선행 조건을 보장해야 하와요.

GameCore DLL 로드·게임 실행·게임 계산의 멀티코어 성능은 이번 시험에서 수행하지 않았사와요. 설치 SDK·기존 게임·MODS·저장 파일도 변경하지 않았답니다.
