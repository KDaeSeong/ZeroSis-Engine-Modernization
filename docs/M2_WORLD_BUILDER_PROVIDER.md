# 지도 형식과 부가 데이터 x64 제공자

2026-09-25 시작. 전체 64비트 엔진 목표의 기반 서비스 작업이며 게임 실행 검증은 별도랍니다.

## 요구사항과 변경 범위

실제 SDK의 `CvWorldBuilderMapTypeDesc`, `CvWorldBuilderMapTypeGroup`, `CvWorldBuilderMapModData`와 지도 읽기·쓰기 계약을 x64로 제공하와요. 호출부는 BNW `CvWorldBuilderMapLoader.cpp`이며, 타입 순서·누락 항목·기본값·열거형·사용자 문자열·지도 부가 데이터의 저장 폭을 원본 x86 구성요소와 대조하와요.

원본 설치 SDK, 게임 EXE/DLL, 지도, MODS, 저장 파일은 변경하지 않사와요. 새 구현과 시험은 이 프로젝트의 Source → Build → 별도 Stage에서 추적하와요. Mod ID, 저장 키, 기존 지도 버전, 규칙과 밸런스 변경은 범위 밖이랍니다.

| ID | 요구사항 | 수용 근거 |
|---|---|---|
| WB01 | 타입 이름의 공유 저장·순서·검색·변환표 보존 | 실제 원본 SDK와 반환값·직렬화 바이트 대조 |
| WB02 | 타입 그룹의 추가·중복·삭제·복사·직렬화 보존 | 원본 비교와 양방향 읽기 |
| WB03 | 지도/타일별 bool·float·string·enum·기본값 보존 | 원본 구성요소의 값·메타데이터·저장 바이트 대조 |
| WB04 | 잘못된 입력과 할당 실패의 상태 보존 | 경계·실패 주입 시험; 원본 차이는 개별 명시 |
| WB05 | 실제 지도 파일과 시나리오 지원 | 설치 지도의 읽기 및 별도 사본 왕복; 형식별 지원을 구분 |
| WB06 | 실제 게임 코드 연결 | 검증된 제공자를 링크한 뒤 미해결 심볼 전후 대조 |

빈 구현이나 고정 성공 반환으로 연결 요구를 없애지 않사와요. 원본 SDK 공개 헤더의 필드·객체 배치·함수 서명을 유지하와요. 길이를 받지 않는 기존 역직렬화 API는 상위 파일 독자가 먼저 범위를 검증해야 하며, 이 제약을 전체 입력 안전성 검증으로 간주하지 않사와요.

## 호출부 검토 항목

`CvWorldBuilderMapLoader::LoadModData`의 Globals 열거형 경로는 전역 필드의 인덱스로 **타일 필드의 열거형**을 조회하와요. 현재 코드에서 발견한 결함 후보이며, 서로 다른 전역/타일 열거형을 사용하는 실행 재현을 확보한 뒤 별도 수정과 회귀 근거를 연결해야 하와요.

## 현재 상태

타입 이름·그룹의 실제 x64 구현을 연결하여 미해결 항목이 **36→33개**로 줄었사와요. 해소한 항목은 타입 설명자 생성, 타입 추가, 그룹 포함 여부의 3개랍니다. 이 타입·그룹 단계에서 지도·지도 부가 데이터 29개와 파일·로그·디버그 4개가 남아 있었으며, 후속 [부가 데이터 통합](M2_WORLD_BUILDER_MOD_DATA.md)에서 16개를 추가 해소해 현재 전체 17개가 남아 있사와요. SDK 헤더·482개 패치·161개 GameCore 오브젝트는 이번 단계에서 변경하지 않았답니다.

## 타입·그룹 계약과 검증

- 타입 이름은 ASCII 대소문자를 구분하지 않는 공유 저장소에서 처음 등록한 표기를 유지하와요. 검색도 이 저장소에 이름을 등록하는 원본 동작을 유지하며 NULL과 빈 문자열은 메모리에서 구분하와요. 저장 시 둘 다 NUL 한 바이트가 되어 읽은 뒤 빈 문자열로 복원되는 원본 형식을 유지하와요. 비ASCII 바이트는 그대로이며 변경된 CRT 로캘의 비교 규칙은 별도 검토 대상이랍니다.
- 그룹은 대소문자를 구분하고 중복·빈 문자열·255바이트를 넘는 이름의 추가를 무시하와요. 각 항목은 한 바이트 길이, 이름 바이트, NUL로 저장하와요.
- 원본 VC9 정적 아카이브와 새 x64 라이브러리를 실제로 호출하여 정상 비교 8개 모드, 의도한 결함 수정 1개 모드, 각 아키텍처의 자료 쓰기와 네 가지 교차 읽기, 후보 경계 검사를 실행했사와요. 총 **25회 실행·5,432회 검사**이며, 이 가운데 후보 경계 검사는 **626회**랍니다.
- 조작 **2,048회씩**의 결과는 원본·x64·별도 Python 모델에서 `18a4fd15`로 일치하와요. 두 아키텍처가 쓴 **112바이트** 자료는 독립 형식 모델과 일치하고 양방향 읽기도 같았사와요.
- 할당 실패 **17건**에서 기존 객체 값이 유지되며 6종 작업의 성공 경로도 확인했사와요. 시험 실행 파일에만 실패 할당기를 연결하고 실제 제품 오브젝트를 그대로 사용하와요. 공유 문자열 저장소의 실패 중 내부 캐시 증가와 전체 메모리 부족 복구까지 입증한 것은 아니랍니다.
- 작업자 4개의 독립 객체 호출 **4,096회**를 확인했사와요. 공유 이름 저장소는 잠금으로 보호하며 동일한 지도/그룹/타입 객체의 동시 수정은 지원 계약이 아니랍니다. 이 결과를 게임 계산의 병렬화·속도 향상으로 계산하지 않사와요.
- 직접 작성한 구현과 시험은 `/MD /W4 /WX`에서 경고 없이 빌드했사와요. 원본 구성요소와 후보의 가져오기를 확인한 뒤 실행했으며 GameCore는 로드하지 않았답니다.

원본 그룹은 자기 자신에게 대입하면 저장 내용이 사라졌사와요. 원본에서 `one`, `two`의 10바이트가 0바이트로 바뀌는 동작을 재현했고, 후보는 같은 10바이트를 보존하와요. 비교 도구는 이 한 줄 차이만 허용하와요. 길이가 있는 역직렬화 API는 잘린 항목·잘못된 종료 문자·NULL 입력을 거부하고 기존 값을 보존하도록 보완했사와요.

참조 프로그램은 부가 데이터의 bool·float·string·enum과 저장 바이트도 관측했지만, 부가 데이터의 x64 구현·양방향 검증은 후속 [통합 기록](M2_WORLD_BUILDER_MOD_DATA.md)에 있사와요. `InitDataEntries`만 호출한 미초기화 값은 비교 기준으로 쓰지 않으며 모든 필드를 공개 기본값 설정 함수로 초기화한 뒤 기록하와요. 지도 전체 읽기·쓰기, 파일 버전별 호환, 실제 지도·시나리오 왕복, Globals 열거형 호출부 수정과 전체 게임 실행도 남아 있답니다.

## 추적과 재현

제품 소스는 `SdkWorldBuilderTypes.cpp`, `SdkWorldBuilderGroups.cpp`이며 빌드·검증 기록은 `evidence/world_builder/types`에 있사와요. 원본은 `evidence/world_builder/reference`, 연결 전후는 `evidence/world_builder/link_before`, `link_after`, `types/link_delta.json`으로 추적하와요. 검토본은 `Stage/WorldBuilderTypes`와 `Stage/GameCore_x64/Providers/WorldBuilderTypes`에 보관하와요.

```powershell
python tools/probe_world_builder.py
python tools/build_world_builder_types.py
python tools/verify_world_builder_types.py
python tools/world_builder_types_evidence.py
```

전체 연결 조사에 `--world-builder-types-provider evidence/world_builder/types/build_result.json`을 추가한 뒤 `stage_world_builder_types.py`, `stage_sdk_x64_port.py`, `verify_project.py`를 순서대로 실행하와요. 제공자 목록이 길어져 Windows 링크 출력 경로 제한에 걸리는 경우에는 전체 제공자 기록을 유지하고 출력 디렉터리 이름만 해시로 줄이도록 조사 도구를 보완했사와요. 연결 도구 오류는 미해결 심볼 해소로 기록하지 않사와요.
