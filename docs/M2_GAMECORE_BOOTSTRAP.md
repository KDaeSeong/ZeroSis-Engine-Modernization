# GameCore의 명시적 초기화·종료

2026-09-26 / 현재 attempt_032의 **600개 패치·수정 SDK 파일 98개·지원 헤더 7개·C++ 오브젝트 161개·제공자 16개**로 정식 x64 연결의 미해결 항목이 **0개**가 되었사와요. AMD64 DLL을 생성하고 기존 진입점과 새 종료·오류 진입점의 내보내기를 확인했사와요. GameCore DLL은 로드하지 않았으며 실제 컨텍스트·새 게임 실행은 아직 검증하지 않았사와요.

DB 후처리의 부분 변경·성공 오보고를 수정하고 실제 SQL의 오류·복구 1,993개 검사와 보유 규칙 DB 두 개의 별도 복사본 비교를 통과했사와요. GC.init의 DB 단계 실패 검사와 지역 로더 참조 반납은 [후속 DB 캐시 단계](M3_DATABASE_CACHE.md)에서 보완했으며, 전체 초기화 복구는 남아 있답니다. [DB 후처리 계약](M3_DATABASE_POSTPROCESS.md)

실행부 연결 조회 실패 시 기존 연결 보존, 재진입·동시 변경 거부, 컨텍스트·연결·전용 힙의 종료 순서를 보완하고 원본·수정본 합계 1,880개 검사를 통과했사와요. 게임 작업 정지와 GC.uninit을 먼저 완료하는 실행부 계약은 남아 있답니다. [연결 소유권과 정확한 시험 범위](M3_HOST_BINDING.md)

DB 로더의 GC 소유 참조는 일반 종료와 초기화 전 컨텍스트 종료에서 모두 반납하도록 보완했사와요. 재시작 64회를 포함한 4,432개 구성요소 검사를 통과했으며, 외부 참조를 종료 전에 반납하는 실행부 계약과 전체 GC 실패 복구는 별도랍니다. [로더 소유권](M3_DATABASE_LOADER.md)

직접 보유 규칙 정보와 문자열 배열은 기존 게임 객체·호스트·경로 탐색기가 정리된 뒤 해제하와요. 부분 적재·미등록 객체 예외 12,924개 구성요소 검사를 통과했으며, 실제 GC 초기화 실패 중단은 후속 범위랍니다. [규칙 정보 정리](M3_INFO_CLEANUP.md)

## 호스트 호출 계약

1. DLL 로딩이 끝난 뒤 기존 `DllGetGameContext`를 호출하와요. 최초 호출이 타이머 요청, 심볼 등록, 컨텍스트 생성을 순서대로 수행하며 성공하면 기존 ICvGameContext1 포인터를 반환하와요.
2. 실패는 null 반환과 `ZeroSisGetBootstrapError`의 Windows 오류 번호로 확인하와요. 초기화 내부의 C++ 예외를 외부 C 진입점으로 내보내지 않사와요.
3. 같은 초기화의 반복 요청은 같은 컨텍스트를 반환하와요. 시작이나 종료 콜백의 재진입은 ERROR_BUSY로 거부하와요.
4. 종료 전에 모든 SDK 어댑터·게임 작업·작업자를 정리하고 소비자 호출을 멈춘 뒤 `ZeroSisShutdownGameCore`를 호출하와요. 반환값이 TRUE인 뒤에만 FreeLibrary를 호출하는 계약이랍니다.
5. 정리 실패는 자원을 가진 상태로 남으며 종료를 재시도할 수 있사와요. DllMain이나 자동 정적 소멸자에 게임 정리를 맡기지 않사와요.

반환된 컨텍스트는 참조 수를 가진 사용권이 아니랍니다. 모든 게임 API 호출을 이 초기화 잠금이 보호하는 것도 아니므로, 실제 상태 소유 호스트의 스레드·수명 계약을 별도로 구현해야 하와요.

## 상태와 실패 처리

정상 경로는 Empty → Starting → Ready → Stopping → Empty랍니다. 시작 도중 실패하면 이미 확보했거나 부분 생성했을 수 있는 컨텍스트, 심볼, 타이머를 역순으로 정리하와요. 정리에 실패하면 CleanupRequired로 남으며, 실패한 자원을 보유한 채 종료 재시도만 허용하와요.

SDK 컨텍스트 생성자는 어댑터 네 개를 unique_ptr로 임시 소유하고 모두 성공한 뒤 기존 필드로 넘기와요. 힙 생성·컨텍스트 할당·어댑터 생성 실패에서는 이전 단계 자원을 회수하와요. 힙 파괴가 실패하면 핸들을 버리지 않으며, 후속 생성으로 덮어쓰지 않사와요. 어댑터의 custom operator new가 null 주소로 생성자를 호출하지 않도록 `Allocate`가 실패를 예외로 전달하와요.

## native 시험의 범위

수명 관리자 **501개 검사**, SDK 컨텍스트 함수 경계 **118개 검사**, 합계 **619개**를 통과했사와요. 시작·정리 실패 12개, 컨텍스트 생성 실패 10개, 힙 파괴 실패의 자원 보존·재시도, 시작·종료 재진입을 포함하와요.

컨텍스트 시험은 SDK의 실제 함수 본문을 추출하여 Windows 힙과 관측 가능한 대체 어댑터 타입으로 실행하와요. 전체 GameCore 컨텍스트를 실행한 결과로 확대하지 않사와요. 동일한 경계 시험의 기존 본문에서 중복 초기화 후 컨텍스트 1개·어댑터 4개가 남고, 부분 생성 실패 후 어댑터 2개·힙 소유권이 남는 것을 재현했사와요. 새 본문은 해당 사례를 통과하고 실제 SDK 161개 컴파일에도 반영됐사와요.

관련 기반 부품 22단계와 지도·파일·로그·디버그 12단계를 새 SDK 기준으로 갱신했사와요. 로그 2,169개, 심볼 1,730개, 파일·지도 2,086개의 독립 검사도 유지하와요. 기존 GameCore의 컴파일 경고 위치 343곳은 별도 잔여 항목이랍니다.

정식 연결을 기준으로 디버그 제외/포함은 3→0, 로그 제외/포함은 1→0, 로그를 제외한 파일 제공자 비교는 2→1이랍니다. 지도와 파일·로그를 제외하되 디버그를 유지한 비교는 15→2, 지도 객체만의 비교는 15→5랍니다. 이전 빌드의 17→4·4→3·3→2 수치는 당시 제공자 구성의 역사적 결과로 보존하와요.
