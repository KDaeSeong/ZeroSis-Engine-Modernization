# SDK 현지화 문장·사전 x64 연결

2026-09-25 / 독립 구성요소 실행 검증이며 전체 게임 실행 검증은 아니랍니다.

## 요구사항과 변경 범위

GameCore가 사용하는 `Localization::String`의 생성·복사·대입·인수 전달·문장 합성·사전 조회를 실제 x64 DLL로 제공하와요. 원본 실행 파일, 설치 SDK, 게임 데이터, MODS, 저장 파일에는 변경을 가하지 않사와요. 원본 ID·저장 키·게임 규칙·밸런스도 변경 범위 밖이랍니다.

`SdkLocalizationValues.cpp`의 실제 공유 문자열 저장, `SdkLocalizationIcu.cpp`의 실제 숫자·대소문자 변환을 새 `SdkLocalizationString.cpp`와 `SdkLocalizationRuntime.cpp`가 사용하와요. 테스트 안에 구현을 복사해 놓은 구조가 아니랍니다. 소비 시험 프로그램은 별도 DLL의 내보낸 함수를 호출하며 연결 지도에서 실제 구현 위치를 확인하와요.

SDK에는 `String`과 내부 렌더러의 friend 선언 2개만 추가했사와요. 필드·객체 배치·가상 함수·공개 함수 서명·저장 형식은 그대로랍니다. 기존 480개 패치는 유지하고 총 482개 패치로 게임 코드 161개를 다시 컴파일했사와요. 이전 기준과 변경 내용은 `define_localization_patches.py`와 편집 장부가 추적하와요.

## 원본에서 관측한 동작

- 문장을 대입할 때 기존 인수는 유지하며, 문자열 인수는 추가 시점의 독립 복사본을 보관하와요.
- `|`는 형태를 나누며, 위치 인수·레이블·중첩 번역 키·성별·특성·복수형 분기를 지원하와요. 분기의 마지막 세미콜론과 숫자·인용·중첩 형태 선택 동작도 비교했사와요.
- 사전은 초기화와 갱신 알림 시 문구의 스냅샷을 만들지만 `HasKey`는 현재 데이터베이스를 조회하와요. 따라서 갱신 전 두 함수의 결과가 달라질 수 있답니다.
- 언어 우선순위와 다른 언어의 대체 문구를 반영하와요. 대체 언어를 끈 상태에서 다른 언어에만 있는 알려진 키는 키 문자열 자체를 돌려주는 원본 동작도 유지하와요.
- 기본 문장은 언어 포인터가 없으며 현재 언어로 합성하와요. 시스템의 현재 언어 객체를 명시적으로 지정해도 그 객체는 언어 전환 때 함께 바뀌는 원본 동작을 유지하와요.
- 로거는 현지화 시스템이 소유하며 교체·해제·종료 때 소멸하와요. 사용자 정의 복수 규칙은 가상 소멸자가 없는 인터페이스이므로 빌려 쓰며 그 기본형으로 삭제하지 않사와요.

## 검증과 명시적인 동작 보완

원본 x86 DLL과 실제 x64 DLL을 **37개 모드 실행**으로 비교했사와요. 일반·인수·숫자·형태·사전·공유 저장·메타데이터·변경·갱신·언어 지정·형태 선택·로거 수명·경계 동작과 복수 규칙 0~20을 포함하와요. 유효한 복수 규칙 16종은 음수와 -250~250 구간을 포함해 **8,496개 결과**를 대조했사와요.

네이티브 비교 프로그램의 검사 수는 **1,987개**, 원본과 같은 관측 기록은 **2,236개**랍니다. 숫자 출력 1,162개는 기존 ICU 내부 시험에 더해 SDK 문장 경유로도 대조했사와요. 로그 문구와 ICU 경고 발생 빈도는 바이트 동등성의 범위에 포함하지 않으며, 원본과 후보 로그를 모두 보관하와요.

다음 두 보완으로 관측 기록 **8개**가 달라지며, 비교기는 정확한 원본·기대값 쌍만 허용하와요. 다른 차이는 실패로 처리하와요.

1. **전체 형태 복수 설정:** 원본 `SetPlurality(size_t)`는 규칙 2에서 값 2를 거부하지만 형태별·문자열 설정은 값 2를 허용하와요. 후보는 공개 계약에 맞춰 모든 형태에 값 2를 설정하고 잘못된 값은 기존 상태를 보존하며 거부하와요. 게임 코드에서는 이 전체 형태 설정의 직접 호출을 찾지 못했사와요.
2. **잘못된 UTF-8 비교:** 원본은 잘못된 바이트를 비교 성공으로 보고하는 반면, 후보는 실패를 반환하고 호출자의 결과값을 보존하와요.

후보 전용 경계 시험 **74개**는 빈 값·잘못된 크기·잘못된 형태·복사·내부 버퍼 대입·누락 인수 추가 후 재시도·NaN 영문 숫자 변환 거부·실패한 사전 초기화·갱신 실패 시 이전 문구 보존·순환 참조 제한·종료와 재초기화를 검증하와요. 작업자 4개의 독립 호출 **1,024회**도 검증했답니다. SDK 호출과 ICU 종료는 재진입 가능한 잠금으로 보호되므로 이 시험은 게임 계산의 병렬화나 속도 향상 증거가 아니와요. 동일한 `String`을 여러 스레드에서 수정하는 기능도 제공하지 않사와요.

직접 작성한 구성요소와 시험은 `/MD /W4 /WX`로 경고 없이 빌드되었사와요. ICU 원본의 기존 경고 77건과 게임 코드의 경고 343개 위치는 별도 기록으로 남아 있답니다.

## 소유권·실패 계약과 남은 범위

`Initialize`는 검증한 데이터 파일을 정렬된 메모리에 소유하고 ICU를 초기화하와요. 진행 중인 호출과 종료는 같은 잠금으로 직렬화하며, `Shutdown`에서 ICU 정리 뒤 데이터 메모리를 해제하와요. 활성 상태의 중복 초기화는 실패하고 기존 상태를 보존하와요. 문자열 파서는 중첩 64단계, 작업 수 100,000회, 출력 16 MiB를 상한으로 두어 순환 참조의 스택 소진을 막아 두었사와요.

사전의 데이터베이스 연결은 `ShutdownDictionary`까지 호출자가 유지해야 하며 다른 데이터베이스 접근도 외부에서 직렬화해야 하와요. 외부에서 만든 언어·복수 규칙의 수명 역시 호출자 책임이랍니다. 설치 ICU 자료의 모든 내부 포맷 검증, 모든 할당 실패 주입, 임의 사용자 정의 언어 수명은 아직 검증 완료 범위가 아니와요.

전체 실제 번역 자료의 모든 문법·모든 메타데이터, 외부 `ParameterTransforms` API와 날짜·시간 변환 API, 전체 호스트 초기화·종료 순서·UI 표시·모드 조합·전체 게임 저장·성능은 남은 관문이랍니다. GameCore 연결 요구는 52개에서 36개로 줄었고, 현지화의 기존 16개는 모두 해소되었사와요. 이 산출물은 필요한 SDK 문장/사전 구성요소이며 전체 현지화 API나 전체 엔진 완성을 뜻하지 않사와요.
